# 模块设计说明

本文按模块分册说明本工程全部 RTL 模块的设计：每模块依次给出功能与原理、接口与关键参数、设计要点、对应测试四部分。内容与仓库 `rtl/` 下源代码一一对应，模块名、端口名、参数名及数值均以代码为准；凡代码未明确之处，本文不做推断。

工程总体形态：单时钟域（125 MHz）同步设计，Verilog-2001 实现。发送链将应用口注入的消息（VLID 前缀信封）经缓冲、BAG 整形调度、组帧后形成完整以太网帧，经 A/B 双网冗余发出；接收链对双网来帧依次执行 MAC 接收、头部解析、VL 查表、完整性检查（IC）、冗余管理（RM）、分片重组，最终按与发送对称的信封形式交付应用口。系统配置（全局寄存器、发送 VL 表、接收 VL 表）与统计读回经顶层 cfg 主机接口完成。

## 第 1 章 顶层与核心

### 1.1 AFDX_top（工程顶层）

#### 功能与原理

AFDX_top 是端系统对外的应用数据接口外壳，内部仅例化协议核心 afdx_es_core 并直通其端口，不含协议逻辑。按官方答疑口径，本接口的语义为：发送方向，应用侧在 tx_data 上注入「VLID（前 2 字节，大端）+ 应用数据」的字节流，tx_valid 的上升沿至下降沿界定一条完整消息，消息长度可超过单帧载荷上限（上限 1471 字节），超长消息由内部完成 IP 分片；接收方向，rx_data 输出处理完毕的应用数据，同样带 VLID 2 字节前缀，与输入信封对称，rx_valid 标记有效。完整以太网帧只存在于端系统内部，不出现在顶层端口上。

#### 接口与关键参数

端口名与顺序与选题指南模板一致，数据与 valid 方向按应用接口语义定义（tx_* 为输入、rx_* 为输出）：

| 端口 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| clk | 输入 | 1 | 时钟信号 |
| reset | 输入 | 1 | 复位信号（同步，高有效） |
| tx_data | 输入 | 8 | 应用发送数据（VLID 2B 前缀 + 载荷） |
| rx_data | 输出 | 8 | 应用接收数据（VLID 2B 前缀 + 载荷） |
| tx_valid | 输入 | 1 | 发送数据有效（上升沿→下降沿为一条消息） |
| rx_valid | 输出 | 1 | 接收数据有效（语义同 tx_valid） |
| tx_ready | 输出 | 1 | 发送通道就绪，恒 1（应用口无反压） |
| rx_ready | 输入 | 1 | 应用侧接收就绪（可不使用） |
| cfg_addr | 输入 | 20 | 配置地址 |
| cfg_wdata | 输入 | 32 | 配置写数据 |
| cfg_we / cfg_re | 输入 | 1 | 配置写 / 读使能 |
| cfg_rdata | 输出 | 32 | 配置读回数据 |
| cfg_rvalid | 输出 | 1 | 配置读有效 |

本模块无参数表；核心参数在例化 afdx_es_core 时以字面量给出（见第 5 章）。

#### 设计要点

- 系统配置（VL 表与全局寄存器）经顶层 cfg_* 引脚完成：配置写入为同步采样、1 拍一写，配置读为 1 拍延迟返回。该引脚组为交付形态增补，使配置通路在纯综合网表中真实存在、可达。
- tx_ready 恒 1 表示端系统随时可接收应用数据；rx_ready 在设计中可不使用。
- 本层保留 GMII 观测信号的内部连线，供仿真抓帧使用，不在顶层增设端口。

#### 对应测试

- `tb_delivery_e2e.v`：纯顶层引脚驱动的交付级端到端用例（零层级引用），覆盖单帧、分片重组、最短帧三类消息的注入与对称交付校验。
- `tb_delivery_short.v`：交付级缩范围用例（1B / 100B / 2000B 各一信封），带里程碑时刻打印。
- `tb_afdx_tx.v`、`tb_afdx_rx.v`：应用口信封驱动的发送端到端与收发回环用例。
- `tb_perf.v`：顶层全链性能与边界专项用例。

### 1.2 afdx_es_core（协议核心顶层）

#### 功能与原理

afdx_es_core 是协议核心的顶层连线模块，汇聚发送链、接收链、配置总线与统计。发送链数据流：应用口信封 → 信封解析器（剥离 VLID）→ host_arb → buf_mgr（缓冲与描述符）→ tx_regulator / tx_scheduler（BAG 整形与调度）→ tx_sn_gen + tx_frame_builder（取序列号并组帧）→ 帧内部流 → 双网 MAC（锁步发出）→ GMII 观测口。接收链数据流：双网 GMII 收流 → rx_path（内含 mac_rx、解析、查表、IC、RM、重组）→ 应用口信封交付。模块内另例化 cfg_bus、ram_init、tick_gen、timebase、stats 与 tx_vl_table，完成配置面与测量面。

信封解析器位于本模块内：以 1 拍流水将载荷字节送入 8 字节吸收 FIFO，消息末字节携带 eop 标记随字节入队，不产生多余字节；帧头 16 位 VLID 取其低位作为发送 VL 表索引。

#### 接口与关键参数

参数（默认值即顶层例化值，见第 5 章）：TX_VL_NUM=128（发送 VL 数）、RX_VL_NUM=4096（接收 VL 数）、TX_SLOTS=32（发送缓冲槽数）、SLOT_BYTES=2048（每槽字节数）、Q_DEPTH=4（每 VL 队列深度）、MAX_MSG=8192（单条消息字节上限）。

端口分四组：应用口（tx_data/tx_valid/rx_data/rx_valid/tx_ready/rx_ready，语义同 1.1 节）；cfg 总线主机侧（cfg_addr/cfg_wdata/cfg_we/cfg_re/config 读回）；GMII 观测口（gmii_a_d/gmii_a_en、gmii_b_d/gmii_b_en，A/B 两网）；时钟与复位。

#### 设计要点

- 配置主侧四信号（cfg_addr/cfg_wdata/cfg_we/cfg_re）为真实输入引脚，由顶层 cfg_* 引脚直入。设计评审阶段曾定位到：若该组信号在核心内部生成而无外部驱动，纯综合时会因零驱动被整体优化，导致发送使能恒无效、整机逻辑被删除；改为顶层引脚直入后消除该问题，此为本工程综合联调中的关键定案。
- 应用口无反压：吸收 FIFO 承接下游就绪信号的瞬态；当队列真正满且 FIFO 将溢出时，整条消息被丢弃并向 buf_mgr 发出 abort 以回收半截入队（不落描述符），待信封结束后恢复；纯 VLID（零载荷）信封不符合帧定义，静默丢弃。
- 发送侧双网 MAC 由编译宏选择集成形态：集成厂商 MAC IP 时例化 mac_ip_top×2，否则例化 RTL mac_tx×2 与 mac_port_if×2，两形态下核心其余接口不变。

#### 对应测试

- `tb_txframe.v`：发送通路全帧对拍（核心集成前形态），输出帧与金标准逐字节比对并独立核算校验和与时序。
- `tb_afdx_tx.v` / `tb_rxpipe.v`：核心级发送端到端与接收通路全链对拍。
- `tb_delivery_e2e.v`：核心与 MAC 集成后的交付级端到端校验。

### 1.3 cfg_bus（配置总线）

#### 功能与原理

cfg_bus 完成配置地址译码、全局寄存器组、写广播分发与读回多路选择。主机经一组同步接口（地址、写数据、写使能、读使能、读回数据、读有效）访问全部配置空间：全局寄存器在本模块内实现；发送 VL 表、接收 VL 表与统计空间的写入以广播脉冲形式分发给各属主模块，读回数据经多路选择返回。读时序为：读使能当拍锁存地址，下一拍读有效置位且读回数据有效（1 拍延迟），RAM 区读数据同为 1 拍。

#### 接口与关键参数

参数 VERSION=32'h20261031（版本寄存器只读值）。端口：主侧 cfg_addr[19:0]、cfg_wdata[31:0]、cfg_we、cfg_re、cfg_rdata[31:0]、cfg_rvalid；全局寄存器直出 g_uid[15:0]、g_src_ip[31:0]、g_tx_en 与输入 init_done；发送 VL 表写广播 cw_we/cw_idx[6:0]/cw_wsel[2:0]/cw_wdata 及表读口 tbl_re/tbl_raddr/tbl_rdata/tbl_busy；接收 VL 表写广播 rxt_we/rxt_idx[10:0]/rxt_wsel/rxt_wdata 及读口；统计读口 stats_re/stats_raddr[9:0]/stats_rdata。完整地址映射见 5.2 节。

全局寄存器组（0x00000~0x00FFF 区）：0x00000 VERSION（只读）、0x00001 UID（读写）、0x00002 SRC_IP（读写）、0x00003 CTRL（读写，bit0 为发送使能 tx_en）、0x00004 STATUS（只读，bit0 为 init_done）、0x00005 CFG_REJ_CNT（只读，VL 表非法写拒收计数）、0x00006 CFG_REJ_FLAG（只读，拒收原因粘滞标志：bit0 为 BAG 非法，bit1 为 net_mask 为 00）。

#### 设计要点

- 发送 VL 表写门禁在本模块截下：W0 的 bag_ms 仅接受 {1,2,4,8,16,32,64,128} 八个取值，W3 的 net_mask 为 00（A/B 均不选）时拒绝。非法写不发出写广播，表、整形器与缓冲管理器均不可见（读回保持旧值），同时拒收计数加一并置位原因标志，供测试断言与运行期诊断。
- 未落地空间（端口分发/管理平面区）读回 0，保证地址空间行为确定。

#### 对应测试

- `tb_cfg.v`：覆盖全局寄存器读写、VL 表写后读回逐字比对（含索引边界）、写门禁对非法 BAG 与非法 net_mask 的拒收及计数/标志、写广播脉冲内容、1 拍读回语义、未映射区读回 0。

### 1.4 timebase（时基）

#### 功能与原理

timebase 产生 64 位纳秒时间：每时钟拍累加 NS_PER_CLK。125 MHz 时钟下每拍 8 ns。该时间用作端到端时延与抖动的测量打点基准。

#### 接口与关键参数

参数 NS_PER_CLK=8。端口：clk、reset、time_ns[63:0]（寄存器输出）。

#### 设计要点

- 采用固定步长累加，无校准逻辑；64 位宽保证测试时长内不回绕。

#### 对应测试

- `tb_cfg.v`：校验 time_ns 恒等于 8×已运行周期数。

### 1.5 stats（统计与抖动记录）

#### 功能与原理

stats 汇总全机运行计数与发送抖动记录。每 VL 设三块计数 RAM（发送帧数、发送载荷字节数、发送最大抖动，均为 32 位，读-改-写更新）；另存每 VL 的 eligible 上升沿时刻 t_elig（24 位 µs），帧完成时以当前 µs 时刻减 t_elig 得到该帧抖动，更新最大抖动 RAM 与全局计数。接收侧汇聚一组单拍事件脉冲（好帧、FCS 错、长度错、MAC 错、VL 未命中、网络不符、IP 头错、IC 丢弃、RM 重复、RM 旧帧、重组超时、交付消息等，见接口），分别计数。全部计数经 cfg 读口读回（地址编码见 5.2 节注记）。

#### 接口与关键参数

参数 TX_VL_NUM=128。输入：tick_us（1 µs 单拍）、elig[127:0]（合成 eligible 向量，检上升沿打点）、st_frame/st_vl/st_paylen（帧完成打点）、ev_enq/ev_qfull/ev_lenerr（入队事件）、一组 ev_rx* 接收事件脉冲与 ev_rxbytes[13:0]（交付消息载荷字节数）；输出 stats_rdata[31:0]（读使能后 1 拍有效）；另有上电清零写口 ri_we/ri_sel/ri_addr（ri_sel=2/3/4 分别对应三块每 VL RAM）。

#### 设计要点

- RAM 读口由 cfg 读回优先；帧完成时的读-改-写在事件当拍切换读地址，下一拍捕获，与 cfg 回读不冲突。
- 每 VL 的 µs 时刻记录为 24 位（约 16.7 s 回绕），与测试时长相容，头注中已注明该边界。
- 三块每 VL RAM 与发送 VL 表、IC/RM 状态等同属上电清零对象（见 1.7 节）。

#### 对应测试

- `tb_sched.v`：调度组集成用例中校验每 VL 计数与全局计数。
- `tb_rxpipe.v`：接收事件计数与期望值比对。
- `tb_afdx_tx.v`：以期望计数断言长度违规拒收等事件（如 g_lenerr）。

### 1.6 host_arb（多主机发送仲裁）

#### 功能与原理

host_arb 在多个发送客户端之间做包级循环仲裁：某客户端的 sop 获准后锁定该客户端，直至其 eop 传完，包内不切换、不打断；包间由 rr_arbiter 轮转决定下一获准者。本工程当前只接入 1 个客户端（应用口），此时模块为纯透传；接口按多客户端形态冻结，后续管理面等客户端可沿同一接口接入。

#### 接口与关键参数

参数 NUM_HOST=1（客户端数，须为 2 的幂）、IW=1（索引位宽）。客户端侧以扁平拼接方式给出：h_valid/h_sop/h_eop（每客户端 1 位）、h_data（每客户端 8 位）、h_vl（每客户端 7 位）、h_ready（回压）。汇聚输出为单路 o_valid/o_sop/o_eop/o_data[7:0]/o_vl[6:0] 与 o_ready。

#### 设计要点

- 仲裁粒度为整包而非字节，保证一条消息的字节流在汇聚口上连续、不与其它客户端交错。
- NUM_HOST=1 时无仲裁开销，逻辑退化为直通，不影响单客户端时序。

#### 对应测试

- `tb_sched.v`：以 NUM_HOST=2 配置校验包级锁定不交错、循环轮转次序与字节完整性。

### 1.7 ram_init（上电清零）

#### 功能与原理

ram_init 在上电后依次向各状态 RAM 写入全 0，产生 init_busy/init_done 指示。需清零的对象为默认状态必须为 0 的存储：发送 VL 表（使能/BAG 等配置位默认 0）、stats 三块计数 RAM、IC 状态 RAM、RM 状态 RAM、接收 VL 表（两块并行）。其余状态存储因遵循「计数寄存器门控、写先于读」的设计约定而免清零。各 RAM 属主按 ri_sel 匹配本模块给出的写使能与地址（多选在核心顶层完成），写数据恒 0。

#### 接口与关键参数

参数：TABLE_WORDS=1024（发送 VL 表字数）、STATS_WORDS=128（stats 每 RAM 字数）、IC_WORDS=8192（IC 状态字数，2 网 × 4096）、RX_WORDS=4096（RM 状态/接收表字数）。输出：init_busy、init_done、ri_sel[2:0]（0=空闲，1=发送表，2/3/4=stats 三 RAM，5=IC，6=RM，7=接收表）、ri_addr[15:0]、ri_we。

#### 设计要点

- 清零完成（init_done=1）之前不应发生配置写入；配置流程须先查 STATUS 寄存器的 init_done 位（见 1.3 节）。
- 采用顺序清零而非并行清零，写口与地址由属主侧多选复用，不为每块 RAM 增设独立清零通道。

#### 对应测试

- `tb_cfg.v`：观测复位释放后清零 busy/done 时序，校验清零完成前表读出为 0、完成后可正常配置。

## 第 2 章 发送链

### 2.1 tx_vl_table（发送 VL 配置表）

#### 功能与原理

tx_vl_table 存储 128 项发送 VL 配置，每项 8 个 32 位字，经配置区 0x01000 起的地址写入。表项布局：W0 为 {使能 en, 保留, bag_ms[7:0]}；W1 为 Smax[15:0]（应用载荷层级上限）；W2 为 VLID[15:0]（完整 VLID，组帧时取作帧头字段）；W3 低 2 位为 net_mask（bit0=A 网，bit1=B 网）；W4 为 phase_us[15:0]（BAG 相位偏移）；W5 为 UDP 源端口 sport；W6 为 UDP 目的端口 dport；W7 保留。

#### 接口与关键参数

参数 TX_VL_NUM=128。写口为 cfg 写广播 cw_we/cw_idx[6:0]/cw_wsel[2:0]/cw_wdata[31:0]；内核读口 rd_idx/rd_wsel/rd_data（1 拍延迟）供组帧器连读表项；cfg 读回口 tbl_re/tbl_raddr[9:0]/tbl_rdata 与上电清零写口 ri_we/ri_addr[9:0]。

#### 设计要点

- 存储为单 RAM，写口归配置侧；唯一读口分时复用：默认给内核读（组帧器连读 8 字），cfg 读回仅在内核读未占用（tbl_busy=0）时切入。内核读永不被配置读回干扰；tbl_busy 期间 cfg 读回得到的是内核读地址的数据，读回自检让位于业务，属明确的设计取舍。
- BAG 合法集合 {1,2,4,8,16,32,64,128} 与 net_mask 非零的写门禁在 cfg_bus 侧执行（见 1.3 节），本模块只负责存储与读出。

#### 对应测试

- `tb_cfg.v`：写入 128 项 × 8 字后逐字读回比对，含索引 127 边界；内核读口 1 拍延迟校验；写门禁拒收后端读回保持旧值。

### 2.2 tx_scheduler（发送调度器）

#### 功能与原理

tx_scheduler 是发送链的任务调度中枢。它从请求向量 req 中经循环仲裁选出一个 VL，发出 task_start 通知组帧器准备该 VL 的一帧；待组帧器给出 frame_ready 后，按该帧的网络掩码 fr_mask 在同一拍启动 A/B 两网 MAC，使两网锁步消费组帧器的同一帧体流，冗余副本同时发出；待两网 MAC 均完成（含各自 FCS 与帧间隔），发出 task_done，并同拍给出统计打点。请求向量在核心顶层合成：regulator 的 eligible、buf_mgr 的队列非空与全局发送使能三者相与。

#### 接口与关键参数

参数 TX_VL_NUM=128。输入 req[127:0]；对组帧器：task_start（单拍）、task_vl[6:0] 输出，bld_busy、frame_ready、fr_mask[1:0]、fr_paylen[13:0] 输入；对 MAC：macA_start/macB_start 输出（单拍），macA_done/macB_done 输入；任务完成 task_done（单拍）与统计打点 st_frame/st_vl/st_paylen 输出。

#### 设计要点

- 双网同拍启动是冗余副本时差指标的实现点：两份副本同拍发出，SFD 时刻一致，满足冗余副本应在 0.5 ms 内先后发出的要求且裕量最大。
- 循环仲裁指针在 task_start 被接受当拍推进，保证获准 VL 在下一轮中优先级最低，VL 间公平。
- 任务粒度为一帧：分片消息的后续帧作为独立任务在后续 BAG 周期再次被调度（见 2.6 节）。

#### 对应测试

- `tb_sched.v`：组帧器与 MAC 以测试桩代替，校验多 VL 轮转次序、任务握手时序与统计计数联动。
- `tb_txframe.v`、`tb_afdx_tx.v`：全链集成下校验帧间隔（BAG）与双网副本时差。

### 2.3 tx_regulator（BAG 整形）

#### 功能与原理

tx_regulator 按 VL 执行带宽分配间隔（BAG）整形：每 VL 一个 17 位 µs 上计数器，计数达到装载的 reload 值即 BAG 到期（bag_ok）。eligible[i] = en & bag_ok，队列非空与全局使能由调度侧合并。配置 W0 写入时装入使能与 reload，同时计数器置为 reload，即配置后立即到期、首发不等待；W4 写入装入 phase_us 至计数器，实现首发相位延迟，供离线调度错开各 VL 的首发时刻。每 µs 节拍计数未到 reload 时加一，到齐保持；某 VL 一帧发出（fs_pulse）时其计数清零，重新计一个完整 BAG，保证相邻帧起始间隔不小于 BAG。

#### 接口与关键参数

参数 TX_VL_NUM=128、IW=7。输入 tick_us（1 µs 单拍）、cfg 写广播 cw_we/cw_idx/cw_wsel/cw_wdata（用 W0/W4）、fs_pulse/fs_vl（帧已发出）；输出 eligible[127:0]。

#### 设计要点

- 以 µs 为计数粒度与 BAG 的毫秒级取值相匹配：reload 最大 128 ms 需 17 位计数（128000 µs），位宽由此确定；全表寄存器预算约为 128×(17+17+1) 位。
- 相位装载与周期装载分离（W4 与 W0），使「首发错峰」与「周期整形」两个语义互不干扰。

#### 对应测试

- `tb_sched.v`：校验 W0 配置即到期、W4 相位延迟量等于 reload 与 phase 之差、一帧发出后精确再隔一个 BAG 到期。

### 2.4 tx_sn_gen（序列号生成）

#### 功能与原理

tx_sn_gen 维护 128 个每 VL 独立的序列号（SN）计数器。序列规则为：复位后首帧 SN=0（复位标记帧），其后在 1~255 间循环，255 回绕至 1，0 不再出现。调度器每帧发起一次读（sn_re 单拍，给出 VL 索引），下一拍 sn_vld 置位并给出 sn_val。A/B 两份冗余副本使用同一 SN：每帧只读一次、只递增一次。

#### 接口与关键参数

参数 TX_VL_NUM=128、SN_FIRST=8'd0、SN_MAX=8'd255。端口：sn_re（单拍）、sn_vl[6:0] 输入；sn_vld、sn_val[7:0] 输出。

#### 设计要点

- SN=0 被赋予「发送端复位」语义，与接收侧 IC/RM 对 SN=0 的特殊处理（见 3.3、3.4 节）首尾呼应，构成复位重同步机制。
- 读出为 1 拍延迟的寄存器输出，与组帧器的取数流水对齐。

#### 对应测试

- `tb_sched.v`：257 次连续读校验 0→1…255→1 回绕序列与 VL 间独立性。
- `tb_afdx_tx.v`：长序列模式校验回绕后及复位后首帧 SN 行为。

### 2.5 tx_frame_builder（组帧器）

#### 功能与原理

tx_frame_builder 每任务组出一帧。它读取发送 VL 表（VLID、net_mask、sport、dport）、buf_mgr 队首描述符（首槽、消息总长、IP ID、待发片号），并向 tx_sn_gen 取得本帧 SN，据此计算分片几何与 IP 头校验和，最后经帧内部流 s_stream 逐字节发出帧体（目的 MAC 至 SN，不含 FCS）。FCS 由发送 MAC 按网各自计算追加；源 MAC 的接口标识字节由发送 MAC 按网替换，本模块该字节恒填 A 网值占位。

分片几何：消息总长不超过 1471 字节时单帧发送，含 UDP 头，UDP Length 为 8+总长；否则分片：第 1 片载荷 1456 字节（含 UDP 头，UDP Length 填 8+消息总长），后续片偏移按 1456+(k−1)×1464 累进（8 字节对齐），每片载荷至多 1464 字节，后续片为纯 IP 分片。IP 总长为 20 加本帧 UDP 段长度；IP 包之后、SN 之前按需填充至最小帧长（填充量为 max(0, 45−IP 总长)）；帧体总长不超过 1514 字节，加 FCS 4 字节后不超过 1518 字节。

#### 接口与关键参数

参数为帧头常量：目的 MAC 常量段 DST_MAC_C0..C3=03/00/00/00、TTL_DEF=64、源 MAC 前 3 字节常量 SRC_MAC_C0..C2=02/00/00。主要端口：调度器握手 task_start/task_vl 输入，bld_busy、frame_ready（单拍，流开始前）、fr_body_len[10:0]、fr_paylen[13:0]、fr_mask[1:0] 输出；VL 表读口 rd_idx/rd_wsel/rd_data；buf_mgr 描述符与载荷走线口（desc_*、pre_addr/pre_data、nx_ra/nx_rd、frag_*）；SN 取数口 sn_re/sn_vl/sn_vld/sn_val；全局寄存器直读 g_uid/g_src_ip；帧内部流 s_valid/s_sop/s_eop/s_data/s_ready。

#### 设计要点

- s_stream 逐字节无气泡：输出数据由字节计数组合选择（头部寄存器直出、载荷直读、填充 0、SN）；载荷读采用流水预取，发出第 k 字节当拍即指向第 k+1 字节地址，与存储 1 拍读延迟对齐；跨槽边界经 next_ptr 组合跟链。消费方未就绪时计数停等，不丢字节。
- frame_ready 在流开始前单拍发出，调度器据此同拍启动双网 MAC 锁步消费（见 2.2 节）。
- 分片几何与验证用参考模型保持同一口径实现，改动须两处同步，头注中已注明该约束。

#### 对应测试

- `tb_txframe.v`：发送通路全帧对拍，帧体逐字节与金标准比对，FCS 与 IP 校验和独立核算。
- `tb_afdx_tx.v`：顶层信封驱动下覆盖单帧与多片消息的组帧结果及时序检查。

### 2.6 buf_mgr（发送缓冲管理器）

#### 功能与原理

buf_mgr 管理发送缓冲：入队侧接收剥离 VLID 后的应用载荷流，按槽池存储并为每条消息生成一个描述符挂入该 VL 的描述符环；出队侧向组帧器提供队首描述符、载荷走线读与分片推进/释放。一条消息占一个描述符（一个队列深度），分片不在入队时预切，而是在出队侧逐帧生成：组帧器每发一片回报 frag_upd，消息最后一帧发出后弹出描述符并按槽链释放全部槽。

存储结构：槽池为 TX_SLOTS×SLOT_BYTES 的 RAM（口 A 入队写、口 B 组帧读）；空闲槽以位图加计数管理（复位全空闲，无需 RAM 初始化）；槽链以 next_ptr 寄存器阵列实现组合读；描述符为 512 项 × 40 位双口 RAM（128 队列 × 深度 4），描述符内容为 {首槽, 消息总长, IP ID, 填充}；队首/队尾/计数为寄存器（复位清零，未写条目永不被读，描述符 RAM 无需上电清零）；分片游标与每 VL 的 IP ID 计数器为寄存器阵列。

#### 接口与关键参数

参数：TX_VL_NUM=128、TX_SLOTS=32、SLOT_BYTES=2048、Q_DEPTH=4、MAX_MSG=8192（=4 槽），及索引位宽 SLW=6、SBW=11、VLW=7、QW=2、CW=3。入队流 htx_valid/htx_ready/htx_sop/htx_eop/htx_data/htx_vl/htx_abort；cfg 写透传（仅用 W1 的 Smax）；队列状态 q_nonempty[127:0]；描述符读 desc_req/desc_vl → desc_vld/desc_slot/desc_len/desc_ipid/desc_fidx（1 拍延迟）；帧完成 frag_upd/frag_last/frag_vl/frag_slot0/frag_len；载荷走线读 pre_addr/pre_data；next_ptr 组合读 nx_ra/nx_rd；事件 ev_enq/ev_qfull/ev_lenerr/ev_frame。

#### 设计要点

- 入队检查在 sop 拍完成：队列深度未满且空闲槽不少于每消息最大占用（4 槽）才接受。该判定在整条消息期间稳定（本 VL 计数只在自身 sop 增长、空闲槽只增不减），故入队中途不停顿。
- 长度与 Smax 检查在 eop 拍完成：总长超过 MAX_MSG 的消息在接收中途即停写并在 eop 丢弃，且保证槽链恰为 4 槽，任意长度消息的释放行走不超过 4 槽；单帧载荷或分片最大片超过该 VL 配置的 Smax 时整条丢弃并计长度错。Smax 影子寄存器复位值为 0xFFFF，表示未配置时不限制。
- 描述符读与载荷读均为 1 拍延迟，与组帧器的预取流水配合（见 2.5 节）。

#### 对应测试

- `tb_bufmgr.v`：自检式单元测试，覆盖单帧入队/描述符/按链回读/弹出释放与槽复用、跨槽消息（2049 字节）回读与分片推进、IP ID 按消息与 VL 独立、队列深度 4 拒收与弹出后继入、Smax 单帧与分片规则拒收、超长消息拒收且无槽泄漏、8192 字节恰好接受、释放行走期间 sop 拒收，以及入队与弹出同拍等竞态定向场景；收尾断言槽池全部回收。

### 2.7 rr_arbiter（循环仲裁器）

#### 功能与原理

rr_arbiter 为 N 路请求提供循环（round-robin）仲裁：从上次获准索引的下一个位置开始轮转，上次获准者本次优先级最低。授权 gnt 与获准索引 gidx 为纯组合输出；update 单拍且授权有效当拍锁存轮转指针。工程中两处使用：N=4（host_arb 包级仲裁）与 N=128（tx_scheduler 的 VL 选择）。

#### 接口与关键参数

参数 N（请求数，须为 2 的幂）、IW（索引位宽）。端口：req[N−1:0]、update 输入；gnt（等于 req 按位或）、gidx 输出。

#### 设计要点

- 组合授权使调度器可在同一拍获得选择结果并推进指针，无额外仲裁延迟。
- 请求数为 2 的幂的约束使轮转扫描以掩码运算实现，头注中已注明。

#### 对应测试

- `tb_lib.v`：校验轮转次序与单请求直通。
- `tb_sched.v`：在 host_arb 与调度器集成场景中校验轮转公平性。

## 第 3 章 接收链

### 3.1 rx_parser（接收头部解析）

#### 功能与原理

rx_parser 对帧体前 42 字节的顺序流做头部解析与检查（以太网头 14 字节 + IP 头 20 字节 + UDP 头 8 字节），逐项给出检查结论并提取字段。检查项：目的 MAC 前 4 字节等于组播常量 03:00:00:00（hp_ok_mac）；EtherType 等于 0x0800（hp_ok_etype）；IP 版本/IHL 为 0x45、协议为 UDP（17）、IP 头校验和正确（校验和域清零后以 csum16 复算，hp_ok_ip）；UDP 长度关系（hp_ok_udp）：单帧要求 UDP Length 不小于 8 且 IP 总长等于 20+UDP Length，首片要求 UDP Length 不小于 9（首片 UDP Length 填整条消息总长，与单片 IP 总长不一致属设计内行为），中片与尾片该项由调用方忽略。任一检查失败由调用方丢弃该帧并计数。

#### 接口与关键参数

无参数。输入 hp_start（单拍启动，随后 42 拍顺序字节）、hp_valid、hp_data[7:0]；输出 hp_done（末字节处理后 1 拍单拍）、四项 hp_ok_* 结论、提取字段 hp_vlid[15:0]（目的 MAC 低 16 位）、hp_sip[31:0]、hp_ipid[15:0]、hp_iptot[15:0]、hp_mf、hp_off[12:0]（片偏移，8 字节单位）、hp_sport/hp_dport/hp_ulen[15:0]。头部处理总耗时 43 拍。

#### 设计要点

- 字节流 1 字节/拍流式处理，不缓存整帧头；全部结论与字段在 hp_done 拍寄存稳定，供串行引擎同拍取用。
- IP 头校验和以字节流自然次序累加（见 4.9 节），与发送侧计算口径一致。

#### 对应测试

- `tb_rxparser.v`：12 帧对拍用例，含正常单帧、最小帧、首片、中片、尾片，以及 EtherType、协议、校验和、版本、UDP 长度、目的 MAC 六类异常变体与跨 VLID 帧；逐帧比对 4 个结论标志与 8 个提取字段，期望值由参考模型独立重算。

### 3.2 rx_vl_lookup（接收 VL 查表）

#### 功能与原理

rx_vl_lookup 存储 4096 项接收 VL 配置，每项 2 个 32 位字。索引取 VLID 低 12 位直接映射，同时以完整 16 位 VLID 做 tag 全比对：低 12 位相同而高 4 位不同的 VLID 映射同一表项且互斥（后写覆盖前写），tag 不符按未命中处理，此为直接映射加 tag 结构的固有语义。表项布局：W0 低 16 位为 VLID tag，bit16 为项使能 en（0 表示未配置，查表未命中），bit17 为 ic_en（完整性检查使能），bit18 为 rm_en（冗余管理使能），bit[20:19] 为 net_mask（bit0=A 网，bit1=B 网），其余保留；W1 低 16 位为 skew_us（SkewMax，微秒），bit[26:16] 为 smax（应用载荷层级上限，0 表示不检查），其余保留。

#### 接口与关键参数

参数 RX_VL_NUM=4096。配置写广播 rxcfg_we/rxcfg_idx[10:0]/rxcfg_wsel/rxcfg_wdata（地址 = 0x10000 + idx×2 + w）；配置读回口与内核查表共用 RAM 读口；上电清零写口 ri_we/ri_addr[11:0]；内核查表口 kr_re/kr_vlid_in[15:0] 输入，kr_vld、kr_hit、kr_ic_en、kr_rm_en、kr_mask[1:0]、kr_smax[10:0]、kr_skew[15:0] 输出。查表时序为：给出 VLID 后 2 拍结果有效（BRAM 同步读 1 拍加译码寄存 1 拍）。

#### 设计要点

- 内核查表优先于配置读回：查表拍配置读回值无效，配置读回仅在无帧在途时进行，与发送 VL 表的读口分时口径一致。
- 两块表 RAM 在上电清零时并行写入，使能位默认 0，即未配置 VL 一律未命中。
- 查表单拍关键路径为 BRAM 读出、16 位比较与字段散出，在 125 MHz 下裕量充足，并经全规模单元测试实测确认。

#### 对应测试

- `tb_rxlookup.v`：全规模用例 — 写入 4096 项 × 2 字并全部读回比对；内核查表扫全部 4096 个 VLID 校验命中与字段；另设 tag 不符与未配置区的未命中用例，并统计查表延迟。

### 3.3 rx_integrity（完整性检查 IC）

#### 功能与原理

rx_integrity 对每帧序列号做完整性检查，状态按（VL × 网络）独立维护 {seen, psn}，存于 8192×9 位 RAM（地址为 {net, vl}）。判决规则（该 VL 的 ic_en 使能时；未使能由调用方旁路）：未见过该 VL（seen=0）或 SN=0，接受；SN 等于 PSN 的下一值，接受；SN 等于下下一值，接受并标记中间丢一帧（accept_lost，窗口第二格）；其余（大跳号或旧帧）丢弃。其中下一值函数为：x 为 255 或 0 时取 1，否则取 x+1。无论接受与否，判决后均强制以本帧 SN 更新 PSN 并置 seen，实现自动重新同步。

#### 接口与关键参数

参数 RX_VL_NUM=4096。输入 ic_start（单拍）、ic_vl[11:0]、ic_net（0=A 网，1=B 网）、ic_sn[7:0]；输出 ic_vld（启动后 1 拍单拍）、ic_verdict[1:0]（0=丢弃，1=接受，2=接受且丢一帧）、ic_psn_old[7:0]（判决时读到的旧 PSN，供测试对拍）；另有上电清零写口 ri_we/ri_addr[12:0]。

#### 设计要点

- 时序为 2 拍流水：启动拍锁存 {vl, net, sn} 并发 RAM 读地址，下一拍读出旧值、组合判决、输出结论，同拍写回新状态。存储为简单双口 RAM，同地址读旧写新无冒险；串行引擎保证同一（VL， 网络）不背靠背判决。
- SN=0 接受规则与发送端「复位后首帧 SN=0」相对应（见 2.4 节），使发送端复位后接收端无需人工干预即可重新同步。

#### 对应测试

- `tb_rxicrm.v`：与冗余管理合并的穷举对拍 — IC 部分对 psn（256）× seen（2）× sn（256）共 131072 个向量逐个注入状态，逐一核对判决与写回。

### 3.4 rx_redundancy（冗余管理 RM）

#### 功能与原理

rx_redundancy 在 IC 通过的帧中做双网冗余去重，实现单一模式：环形距离窗。每 VL 维护 {valid, rsn, t_last}（t_last 为 µs 时刻），存于 4096×33 位 RAM。判决规则（rm_en 使能时；未使能由调用方旁路，双网帧全部交付）：无有效状态（复位后首帧），接受；本帧与上一接受帧的到达间隔超过 SkewMax，接受并重同步；环形距离 d 为 0，判为重复副本，丢弃（先到者胜）；d 在 1~127（RM_WIN）之间，判为递增新帧，接受；其余（128~255）判为旧帧或严重乱序，丢弃。距离以模 255 环形距离计（序列号在 1~255 环上比较）。接受时写回 {valid=1, rsn=本帧 SN, t_last=当前 µs}；丢弃不更新状态。

SN=0 的处理：SN=0 属发送端复位旁路，同时做 SkewMax 窗内副本去重 — 若上一接受帧即 SN=0 且本帧到达间隔不超过 SkewMax，判为同一复位帧的双网副本，丢弃；否则视为发送端再次复位，接受并将 RSN 重置为 0。

#### 接口与关键参数

参数 RX_VL_NUM=4096、RM_WIN=8'd127（距离窗上限）。输入 rm_start（单拍）、rm_vl[11:0]、rm_sn[7:0]、rm_skew[15:0]（该 VL 的 SkewMax，须保持至判决有效拍）、tick_us；输出 rm_vld（启动后 1 拍单拍）、rm_accept（1=接受转发，0=丢弃）、rm_rsn_old[7:0] 与 rm_us[23:0]（观测输出，供测试对拍）；另有上电清零写口 ri_we/ri_addr[11:0]。

#### 设计要点

- 到达间隔 elapsed 以 24 位 µs 计数差计（模 2^24 回绕），与 SkewMax 比较决定超窗接受。
- 距离窗的等价性已经穷举对拍确认：本模块距离式与模 255 映射式在 SN=0 走旁路的前提下全域等价（见对应测试）。
- 本模块只实现环形距离窗单一模式，为设计定案口径，头注中已注明。

#### 对应测试

- `tb_rxicrm.v`：RM 部分对 rsn（256）× sn（256）× 3 组（elapsed， skew）组合加初态 256，共 196864 个向量穷举对拍，逐一核对接受/丢弃判决与状态写回。

### 3.5 rx_reassembly（分片重组）

#### 功能与原理

rx_reassembly 将同一消息的 IP 分片重组为完整载荷。设 2 个并行消息上下文，键为（VL， IP ID）；每上下文含 8 KB 载荷缓冲、1024 位块位图（8 字节/块，与片偏移粒度一致）及 {总长， 已收字节， 总长已知标志， 最大终点， 尾片信息} 等状态。单帧报文（MF=0 且偏移 0）不经本模块。引擎在 RM 接受分片后经写入通道送入：先以 f_alloc 占座（同键上下文已在座则复用，支持乱序中片/尾片先到建上下文；无空座则整帧丢弃并计上下文异常），再以 f_start 启动一片，随后逐字节写入本片载荷，片尾做完整性判定。

片尾接受不变量：全部分片落入 [0, total) 内、两两不重叠、长度和等于 total、唯一尾片终点等于 total，四者成立即推出 [0, total) 全覆盖。违反任一（位图重叠、总长越界、先到片终点回溯不符、总长已知后片终点超限、出现第二个 MF=0 片、尾片终点不等于总长）即整上下文终止释放；尚不齐备则不终止，等待后续片补齐。齐备时发出 f_done，等引擎以 r_start 读出：逐字节流出完整载荷，末字节拍由引擎同拍确认后释放上下文。忙且未齐备的上下文按 µs 计时（片尾续期），达到重组超时（TIMEOUT_W=10000 µs，即 10 ms）释放并发出超时脉冲，残片不交付。

#### 接口与关键参数

参数 MAX_MSG_W=14'd8192（单条消息上限，与核心 MAX_MSG 一致）、TIMEOUT_W=14'd10000（重组超时，µs）。片写入通道：f_alloc/f_vl[11:0]/f_ipid[15:0] 输入，f_alloc_ok（组合回显有无空座）输出，f_start/f_off8[9:0]/f_len[10:0]/f_mf/f_udplen[15:0]/f_data/f_valid 输入，f_busy/f_done/f_done_ctx[1:0]/f_aborted/f_abort_ctx[1:0]/f_timeout/f_to_ctx[1:0] 输出。读出通道：r_start/r_ctx[1:0]/r_ack 输入，r_data/r_valid/r_last/r_total[13:0] 输出。另有 tick_us 输入。

#### 设计要点

- 总长由首片的 UDP Length 推出（total = udplen − 8）；首片后到时，以已到分片的最大终点与尾片终点回溯校验总长一致性，防止错误总长污染上下文。
- 位图置位在片尾一拍完成（掩码为自片偏移起 ceil(len/8) 个块），已收字节按片累加，齐备判定为「已收等于总长且首尾片均已见」。
- 上下文数为 2 是明确的容量定案；上下文占满时新消息整帧丢弃并计数，不排队、不阻塞引擎。

#### 对应测试

- `tb_rxasm.v`：8 个场景对拍 — 在序 2/3/6 片、乱序、缺中片（终止）、缺尾片（超时，测试中将超时参数缩小加速）、重叠（终止）、缺首片（终止），另含上下文占满时 f_alloc_ok=0 的检查；期望由参考模型的重组函数生成。

### 3.6 rx_path（接收通路顶层）

#### 功能与原理

rx_path 是接收链顶层：例化 A/B 两网 mac_rx，各带 2 槽帧缓冲与描述符；串行引擎在两网描述符间轮替选帧，对每帧依次执行 rx_parser 头部检查（查表在头部读取期间重叠进行）、rx_vl_lookup、rx_integrity、rx_redundancy；单帧报文载荷送入交付字节 FIFO，分片报文送入 rx_reassembly，齐备后读出送同一 FIFO；最终经 hrx 接口（sop/eop/port/meta 形态）做应用口信封格式化，输出 VLID 2 字节大端前缀加载荷，与发送注入信封对称。本模块同时汇聚全部接收侧事件计数输出至 stats。

#### 接口与关键参数

参数 RX_VL_NUM=4096。输入：双网 GMII 收流 rxd_a/dv_a/er_a、rxd_b/dv_b/er_b；cfg 接收 VL 表广播与读回口（转 rx_vl_lookup）；上电清零三组写口（IC/RM/接收表）；tick_us 与 time_ns[63:0]。输出：事件脉冲组 ev_rxframe/ev_fcserr/ev_lenerr/ev_macerr/ev_vlunk/ev_neterr/ev_iperr/ev_icerr/ev_rmdup/ev_rmold/ev_fragto/ev_ovf/ev_ctxerr/ev_rxmsg 及 ev_rxbytes[13:0]；应用接收口 rx_data[7:0]/rx_valid。

#### 设计要点

- 串行引擎节拍经核算不积压：每帧处理约为帧头 43 拍 + SN/IC/RM 约 8 拍 + 载荷搬运 N 拍，而线上背靠背帧的最小间隔拍数（帧长加前导与帧间隔开销）大于该值，满线速背靠背输入不积压。
- 交付字节 FIFO 深 16384 字节：单条消息（上限 8192 字节）可全量驻留，另留跨消息裕量。
- 查表触发点在头部第 7 拍（VLID 字节已出），使查表与头部其余字节的解析重叠，缩短引擎关键路径。
- 分片载荷长度的 8 字节对齐性在查表后环节校验，不满足者拒绝进入重组。
- 本工程不做多端口 CAM 分发，hrx 的 port 字段恒 0；该功能不在本期范围，头注中已注明。

#### 对应测试

- `tb_rxpipe.v`：接收通路流水级全链对拍 — 双网 GMII 激励文件独立回放，交付消息逐条逐字节比对，事件计数比对，并实测孤帧端到端时延（首字节入至交付首字节）。
- `tb_afdx_rx.v`：顶层回环用例（发送链发出、回灌接收链），按 VL 分组比对交付序列并实测端到端时延。

## 第 4 章 MAC 与接口

### 4.1 mac_ip_top（MAC IP 集成适配层）

#### 功能与原理

mac_ip_top 是厂商三速以太网 MAC IP（Tri_Mode_Ethernet_Mac）的集成适配层，每网例化一套，A/B 共两例。其职责是把组帧器的帧体流适配到 IP 的用户发送口：发送方向，帧体经 TX 适配（源 MAC 接口标识字节按本网替换 + skid 缓冲）送入 IP 的 tx_axis 流接口，IP 自行添加前导、SFD 与 FCS 并经 GMII 发出；适配层同时给出与 RTL mac_tx 对齐的 start/done 语义：done 在发送使能下降沿后再计 12 拍（帧间隔计费口径与 mac_tx 一致），保证 BAG 重启时刻逐拍一致。A/B 两例共享同一 125 MHz 时钟、同拍收到同一帧体流，副本同时发出。

接收方向不使用 IP 的接收流接口：该口的时钟域源自 PHY 读到的速率，纯仿真无外接 PHY 时不可控；本设计接收走 RTL mac_rx（见 4.3 节），其 GMII 输入与 IP 的 GMII 输出兼容。故 IP 接收侧复位拉低抑制，接收流输出悬空；IP 的 GMII 发送输出经片内回环（1 拍）接至 mac_rx 构成仿真收发闭环。

#### 接口与关键参数

参数 NET_ID=2'b01（01=A 网，10=B 网，观测标注）、IF_ID_BYTE=8'h20（A 网；B 网为 8'h40）。端口与 mac_tx 兼容：start（单拍）、body_len[10:0]、s_valid/s_ready/s_sop/s_eop/s_data 输入，done（单拍）输出；GMII 输出 gmii_d/gmii_en/gmii_er 与帧边界 frame_start/frame_end（单拍）；回环 GMII 输出 lb_gmii_d/lb_gmii_dv/lb_gmii_er；接收事件输出恒 0（接收事件由 rx_path 内 mac_rx 产生）。

#### 设计要点

- MDIO 在纯仿真下挂接虚拟 PHY 从机（见 4.6 节）应答状态寄存器读，使 IP 内部读得千兆速率与链路有效；真实硬件接外接 PHY 时去除该仿真件。
- IP 源文件为 EDA 工具的加密源，仅综合工具可读；功能仿真时以同端口、同行为口径的行为模型（见 4.5 节）替代编译，本模块接口不变。

#### 对应测试

- `tb_delivery_e2e.v`：经行为模型链路完成顶层交付级端到端校验（发送适配、回环、接收全链）。
- `tb_delivery_short.v`：缩范围交付用例，用于综合后网表仿真的主要业务验证。

### 4.2 mac_tx（发送 MAC）

#### 功能与原理

mac_tx 是 RTL 发送 MAC：接收组帧器的帧体流（目的 MAC 至 SN，不含 FCS），完成前导码与 SFD 插入、FCS 计算与追加（低字节先发）、帧间隔（IFG）生成与帧边界门控，经 GMII 发出。帧体的源 MAC 接口标识字节（帧体第 11 字节）按本网替换后再参与 CRC 计算，故 A/B 两网的 FCS 不同。两个实例由调度器同拍启动、锁步消费同一帧体流，副本同时发出。

#### 接口与关键参数

参数 IF_ID=3'b001（A 网；B 网 3'b010）、IF_ID_BYTE=8'h20（A 网；B 网 8'h40）。输入 start（单拍）、body_len[10:0]（帧体字节数，不含 FCS）、帧体流 s_valid/s_sop/s_eop/s_data 与输出 s_ready；GMII 输出 gmii_d[7:0]/gmii_en（前导+SFD+帧体+FCS 期间为 1）；done（单拍，FCS 与 IFG 完毕）输出。

#### 设计要点

- 内置 8 字节吸收 FIFO：start 后组帧器即流式送数，MAC 发前导的 8 拍期间由 FIFO 吸收，其后 1 字节/拍弹出，前导与帧体无缝衔接，无拖尾与空洞；s_ready 即 FIFO 未满。
- CRC32 采用反射多项式实现（见 4.8 节），初值与终值异或均为全 1，结果与通用 CRC32 口径一致。

#### 对应测试

- `tb_txframe.v`、`tb_afdx_tx.v`：全帧对拍中校验前导/SFD、帧体、按网 FCS 与帧间隔；抓帧仅采样发送使能有效拍。

### 4.3 mac_rx（接收 MAC）

#### 功能与原理

mac_rx 是 RTL 接收 MAC，完成接收链前两级处理：SFD 同步（容忍任意前导长度）、逐字节写入环形帧缓冲并在线计算 CRC32、帧长检查（64~1518 字节）、FCS 校验，最终推出帧描述符。工作过程：空闲态在接收有效期间寻找 SFD 字节 0xD5，找到即进入帧体接收（前导字节不入缓冲）；帧体（含 FCS 4 字节）全部计入帧长并写入 2 槽环形缓冲（每槽 2048 字节）；CRC 覆盖全部帧体字节，接收有效下降沿时以魔数残差判定 FCS 正误。坏帧（FCS 错、长度越界、接收错误信号）直接丢弃并计数，槽位回滚复用；两槽全忙时整帧旁路丢弃并计溢出。

#### 接口与关键参数

参数 NET_ID=2'b01（01=A 网，10=B 网）。输入：time_ns[63:0]（SFD 拍打戳）、GMII 接收 rxd[7:0]/rx_dv/rx_er；帧缓冲读口 rd_addr[11:0]（{槽， 偏移}）→ rd_data（1 拍延迟）；描述符出队（FWFT 形态）desc_vld/desc_slot/desc_len[10:0]（完整帧长，含 FCS）/desc_ts[63:0] 与 desc_re 弹出；槽位归还 ret_valid/ret_slot；事件 ev_frame/ev_fcserr/ev_lenerr/ev_overflow。

#### 设计要点

- 描述符 {槽， 帧长， 时间戳} 经同步 FIFO 以 FWFT 方式给出，时间戳为 SFD 拍的时基值，供上层时延测量使用。
- 槽位归还由引擎在处理完一帧后显式发出，写读两端经 2 槽解耦，引擎处理一帧期间另一槽可继续接收。

#### 对应测试

- `tb_rxpipe.v`：双网各一实例参与接收全链对拍，好帧交付与坏帧计数均经事件比对覆盖。
- `tb_afdx_rx.v`：回环链路中与发送链闭环验证。

### 4.4 mac_port_if（端口契约适配）

#### 功能与原理

mac_port_if 是 MAC 与外部之间的端口契约适配层，隔离集成形态差异：纯仿真形态下，A/B 两网 GMII 观测直通，并由发送使能边沿生成帧起始/结束选通供测试抓帧；集成厂商 MAC IP 时，本模块改为对接 IP 的客户端/GMII 契约，核心内部其余接口不动。

#### 接口与关键参数

参数 NET_ID=2'b01。输入 tx_d_in[7:0]/tx_en_in（来自 mac_tx 的 GMII 发送侧）；输出 gmii_d/gmii_en 直通、gmii_er 恒 0（无错误注入）、frame_start（使能上升沿单拍）、frame_end（使能下降沿单拍）。

#### 设计要点

- 差异收敛于单一模块：发送链其余部分不感知后端是 RTL MAC 观测口还是厂商 IP 契约口。

#### 对应测试

- `tb_txframe.v`、`tb_afdx_tx.v`：经本模块的帧边界选通定位抓帧并参与全帧对拍。

### 4.5 mac_ip_behav（MAC IP 行为模型，仿真用）

#### 功能与原理

mac_ip_behav 提供与厂商 MAC IP 同名、同端口的行为模型（模块名 Tri_Mode_Ethernet_Mac），仅用于功能仿真回归，综合与综合后仿真以厂商 IP 网表为准。行为口径：发送为流式（不存储转发）— 空闲态检到首字节后先插前导 7×0x55 与 SFD 0xD5，输入字节经 4 深吸收队列不丢，随后 1 字节/拍直通帧体，末字节后补发 FCS32（低字节先发），其后发送使能落下；发送就绪信号仅在帧发送期拉低（同一时刻只发一帧）。接收流接口在接收复位有效时恒无效（本设计接收走 RTL mac_rx）。MDIO 主机时序不复现（虚拟 PHY 在适配层应答，本模型不依赖）。

#### 接口与关键参数

端口与 IP 用户指南的接口表一致，分七组：用户发送口（gtx_clk、tx_mac_rst_n、tx_mac_aclk、tx_axis_mac_* 流接口）、用户接收口（rx_mac_rst_n、rx_mac_aclk、rx_axis_mac_*、rx_axis_filter_tuser）、PHY 接收口（eth_rx_clk、mii_tx_clk、eth_rx_*、col、crs）、PHY 发送口（eth_tx_clk、eth_tx_er、eth_tx_en、eth_txd）、MDIO（mdio_rst_n、mdio_clk、mdc、mdio）、用户控制口（sys_rst_n、link、speed[1:0]、user_duplex_mode、user_port_mode、phy_addr、user_wr_*/user_rd_*、mac_filter_*、pause_*、sour_mac_addr）。时钟口径为 gtx_clk 单域 125 MHz（千兆）。

#### 设计要点

- 行为模型只复现本设计实际使用的发送路径与状态口径，不追求 IP 全功能等价；其存在意义是使交付级用例可在功能仿真中以与综合相同的拓扑运行。

#### 对应测试

- `tb_delivery_e2e.v`：例化本模型（经同名包装）构成顶层回环链路完成 6 条消息交付校验。

### 4.6 mdio_phy_sim（虚拟 PHY，仿真用）

#### 功能与原理

mdio_phy_sim 是仿真用虚拟 PHY，实现 MDIO（Clause 22）从机的最小子集。背景：MAC IP 复位后经 MDIO 自动读 PHY 状态寄存器以确定速率与链路状态；纯仿真无外接 PHY，本模块在 MDIO 线上应答读操作，返回预置的 BMCR/BMSR 值（千兆、全双工、链路有效），保证 IP 内部读得速率编码 2'b10、链路为 1。协议处理为：前导任意，随后起始位、读操作码、PHY 地址、寄存器地址、转向位，最后由从机 MSB 先驱动 16 位数据。本模块为纯寄存器与移位逻辑，可综合，真实硬件时去除并将 MDIO 接外接 PHY。

#### 接口与关键参数

参数 BMCR_VAL=16'h0140（寄存器 0 预置值：千兆位与全双工位）、BMSR_VAL=16'h0024（寄存器 1 预置值：自动协商完成位与链路有效位）。端口仅 mdc 输入与 mdio 双向线。

#### 设计要点

- 只应答读操作，不实现写与完整寄存器组，体积可忽略。

#### 对应测试

- 无独立单元测试；随 mac_ip_top 的集成仿真（`tb_delivery_e2e.v` 链路）验证 IP 能正确读得速率与链路状态并完成发送。

### 4.7 sync_fifo（同步 FIFO）

#### 功能与原理

sync_fifo 是单时钟同步 FIFO，带计数与 almost_full 标志，采用 FWFT 读口径：读数据恒指向队首，读使能在当拍弹出当前队首。满时写被忽略、空时读被忽略，调用方须先看满/空标志。工程中用于各处字节/描述符缓冲（如发送 MAC 吸收、描述符队列、信封吸收与交付缓冲的构成件）。

#### 接口与关键参数

参数 DW=8（数据位宽）、DEPTH=16（深度，须为 2 的幂）、AW=4（指针位宽）、AF_LEVEL=14（almost_full 阈值，计数不小于该值时置位）。端口：we/wdata 写口，re 读使能，rdata（队首值），full、empty、count[AW:0]、almost_full 状态输出；复位为同步高有效。

#### 设计要点

- 深度限定为 2 的幂，环形指针自然回绕，无需额外比较逻辑。

#### 对应测试

- `tb_lib.v`：校验 FWFT 读口径、计数、almost_full 与满行为。

### 4.8 crc32_d8（CRC32 校验）

#### 功能与原理

crc32_d8 为每拍 8 位并行 CRC32：采用反射多项式 0xEDB88320（即 0x04C11DB7 的位反序），初值与终值异或均为 0xFFFFFFFF。用 init 单拍开启新帧计算（寄存器置全 1），随后按字节流逐拍喂入数据；fcs 输出为寄存器取反，发送侧按低字节先发。结果与通用 CRC32（如 zlib.crc32）一致；自测锚点：字符串 "123456789" 的 CRC 为 0xCBF43926。发送 MAC 的 FCS 生成与接收 MAC 的在线校验共用本模块口径。

#### 接口与关键参数

无参数。端口：init（单拍）、valid、data[7:0] 输入；crc[31:0]（内部寄存器值，未取反）、fcs[31:0]（取反后的最终值）输出；复位为同步高有效（寄存器复位到全 1 初值）。

#### 设计要点

- 8 位并行展开使 1 字节/拍的线速处理无停顿，与 GMII 字节节拍一致。

#### 对应测试

- `tb_lib.v`：4 组向量对拍（标准校验串、全 0、全 1、伪随机长串），金标准由脚本侧 CRC32 独立计算。

### 4.9 csum16（反码校验和）

#### 功能与原理

csum16 是 16 位反码求和累加器，供 IP/UDP 头校验和的生成校验共用口径。按字节输入：clr 单拍清零开始新计算；有效字节按出现次序交替作为 16 位字的高、低字节（网络字节序流的自然累加），进位回卷；csum 输出为累加和取反，可随时读取（读前须确保已喂完）。最后为奇数字节时需调用方补一个 0x00 字节再出结果；IP 头恒 20 字节为偶数，无此问题。接收侧头部解析用其复算 IP 头校验和；发送侧校验和由组帧器按寄存器直算，口径一致。

#### 接口与关键参数

无参数。端口：clr（单拍）、valid、data[7:0] 输入；csum[15:0] 输出。

#### 设计要点

- 字节流式累加与头部解析的逐字节处理天然同步，无需缓存整个头部。

#### 对应测试

- `tb_lib.v`：样例 IP 头校验和对拍（期望 0x8DC9，由参考模型独立给出）及 clr 后复算。

### 4.10 sdp_ram（简单双口 RAM）

#### 功能与原理

sdp_ram 是简单双口 RAM 推断模板：端口 A 同步写，端口 B 同步读（读延迟 1 拍）；写读同地址当拍读出旧值，调用方自行避开同址读写冒险。Verilog-2001 编写，综合时按双口 BRAM 推断。工程中各状态/数据存储（VL 表、IC/RM 状态、缓冲等）均以此模板或其口径构成。

#### 接口与关键参数

参数 WIDTH=8（数据位宽）、DEPTH=1024（条数）、AW=10（地址位宽，例化方按深度给定）、INIT_EN=0 与 INIT_FILE=""（可选的仿真初始化文件）。端口：we/waddr/wdata 写口，raddr 输入，rdata 输出（1 拍读延迟）；单时钟域 125 MHz。

#### 设计要点

- 读旧写新的确定语义被 IC/RM 等「读旧值判决、同拍写回」的状态模块依赖（见 3.3、3.4 节）。

#### 对应测试

- `tb_lib.v`：校验写后读数据与 1 拍读延迟。

### 4.11 tick_gen（微秒节拍发生器）

#### 功能与原理

tick_gen 以相位累加方式产生精确的 1 µs 单拍节拍：每拍累加 NS_PER_CLK，累加满 TICK_NS 输出一个单拍 tick。125 MHz 下每拍 8 ns，1000/8=125 整除，tick 严格每 125 拍一次、无累积误差；每拍纳秒数非整除时余数保留在累加器，同样无长期漂移。该节拍供 BAG 整形（tx_regulator）、RM 时间窗（rx_redundancy）、重组超时（rx_reassembly）与统计（stats）共用。

#### 接口与关键参数

参数 NS_PER_CLK=8、TICK_NS=1000。端口：clk、reset 输入，tick（单拍脉冲）输出。

#### 设计要点

- 相位累加结构使节拍周期不依赖时钟频率取整，换时钟频率时仅改参数。

#### 对应测试

- `tb_lib.v`：校验 125 拍周期。

## 第 5 章 配置与参数总表

### 5.1 顶层例化参数

AFDX_top 本身无参数表；其例化 afdx_es_core 时以字面量给出的参数如下（与 afdx_es_core 参数默认值一致）：

| 参数 | 值 | 含义 |
|---|---|---|
| TX_VL_NUM | 128 | 发送 VL 条数 |
| RX_VL_NUM | 4096 | 接收 VL 条数 |
| TX_SLOTS | 32 | 发送缓冲槽数 |
| SLOT_BYTES | 2048 | 每槽字节数（2 KB） |
| Q_DEPTH | 4 | 每 VL 发送队列深度（条） |
| MAX_MSG | 8192 | 单条消息字节上限（=4 槽） |

核心内部总线与时间参数：系统时钟 125 MHz（每拍 8 ns）；µs 节拍由 tick_gen 产生（见 4.11 节）。

### 5.2 配置地址映射总表

配置空间经 cfg_bus 译码（见 1.3 节），地址宽 20 位：

| 地址区 | 内容 | 说明 |
|---|---|---|
| 0x00000~0x00FFF | 全局寄存器 | 0x00000 VERSION（只读，值 32'h20261031）；0x00001 UID；0x00002 SRC_IP；0x00003 CTRL（bit0=发送使能）；0x00004 STATUS（bit0=init_done，只读）；0x00005 CFG_REJ_CNT（只读）；0x00006 CFG_REJ_FLAG（只读） |
| 0x01000~0x01FFF | 发送 VL 表 | 128 项 × 8 字，地址 = 0x01000 + VL×8 + 字选；布局见 5.3 节 |
| 0x10000~0x17FFF | 接收 VL 表 | 4096 项 × 2 字，地址 = 0x10000 + idx×2 + w（bit0 为 W0/W1 字选）；布局见 5.4 节 |
| 0x20000~0x2FFFF | 统计读回 | 地址低 10 位编码 {vl, sel}：每 VL 三项（帧数/载荷字节/最大抖动）与全局计数一组（发送与接收事件计数），编码细节以 cfg_bus 与 stats 源代码为准 |
| 其余 | 未落地空间 | 读回 0（端口分发/管理平面区，本期未实现） |

读时序统一为 1 拍延迟：读使能当拍锁存地址，下一拍读有效且数据有效。

### 5.3 发送 VL 表项布局

每项 8 个 32 位字（见 2.1 节）：

| 字 | 字段 | 说明 |
|---|---|---|
| W0 | en（bit31）、bag_ms[7:0] | BAG 毫秒值，合法集合 {1,2,4,8,16,32,64,128}，其余位保留 |
| W1 | Smax[15:0] | 应用载荷层级上限（每帧 UDP 载荷字节上限）；影子寄存器复位值 0xFFFF 表示未配置不限制 |
| W2 | VLID[15:0] | 完整 VLID，组帧取作帧头字段 |
| W3 | net_mask[1:0] | bit0=A 网，bit1=B 网；00 为非法配置，写时拒收 |
| W4 | phase_us[15:0] | BAG 相位偏移（µs） |
| W5 | sport[15:0] | UDP 源端口 |
| W6 | dport[15:0] | UDP 目的端口 |
| W7 | — | 保留 |

### 5.4 接收 VL 表项布局

每项 2 个 32 位字（见 3.2 节）：

| 字 | 字段 | 说明 |
|---|---|---|
| W0 | vlid[15:0]（tag）、en（bit16）、ic_en（bit17）、rm_en（bit18）、net_mask（bit[20:19]） | en=0 表示未配置（查表未命中）；其余位保留（写 0） |
| W1 | skew_us[15:0]、smax（bit[26:16]） | skew_us 为 SkewMax（µs）；smax 为应用载荷层级上限，0 表示不检查；其余位保留（写 0） |

索引为 VLID 低 12 位直接映射，tag 为完整 16 位 VLID 全比对。
