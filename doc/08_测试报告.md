### 6.4 根因定位：.vqm 默认端口省略与原语模型默认驱动缺失（2026-11-04）

- 现象回顾：§6.2、§6.3 两跑的共同特征——仿真时间正常推进、配置与注入里程碑按时出现、交付恒为 0、无任何错误行。该形态提示故障不在某条数据通路，而在全设计范围的共因。另经自审确认：两份交付 TB 从不回读任何寄存器，cfg-done 与注入里程碑仅为 TB 自报动作完成，并非 DUT 侧证据，故障段实际可在配置到交付的任意一段。
- 机制（端口层）：eLinx 综合交换网表 .vqm 对取默认值的 lcell 端口一律省略不写，其中寄存器使能 ena 的默认值应为 VCC（布局布线按此补全）；而 eLinx 仿真原语库 elinx_atoms.v 中 stratix_lcell 的 ena 仅声明为普通 input（第 996 行），未像 devpor/devclrn（第 1013 行 tri1）那样声明默认上拉。端口悬空在仿真中为 Z、经缓冲为 X，模型装载条件 iena === 1'b1 永不成立——**凡网表中未显式连接 .ena 的寄存器，自上电起冻结于 0（power_up="low"），永不装载**。
- 规模与互证（变体网表）：lcell 共 48,266 个；§6.3 跑的日志中 vopt-2718「Missing connection for port 'ena'」告警实数 30,284 条，与适配脚本统计的待补 ena 数 30,284 逐条一致；其中带时钟的寄存器 1,145 个（全量网表 2,245 个）。抽样实例 \afdx_es_core:u_core|mac_ip_top:u_macB|rst_sh[0]~I 仅有 .clk/.dataa/.aclr、无 .ena，告警行号（55678 等）恰指向该批实例。冻结名单横跨各段：buf_mgr 空闲槽位图（恒 0 即无槽可用）、发送调度状态、stats 全部计数器、cfg_bus 回读地址寄存器、ram_init 状态机——ram_init 状态冻结值 0 恰为其 S_DONE 编码，故 init_done 在门级呈假性恒 1、清零序列从未执行。该机制同时解释：RTL 同 TB 通过（RTL 仿真无 WYSIWYG 端口省略）、更换 MAC 变体同墙（冻结在 core 本体）、无错误行（无字节流出）。
- 排除项：RAM 块在原语模型中 t=0 清零且写使能带默认上拉，RAM 初值/写口假设排除；寄存器上电值为 0 而非 X，问题不在初值而在永不装载。
- 第二层省略——参数 defparam（微探针定位，见 §6.5）：.vqm 同样不写 defparam。stratix_lcell 在 arithmetic 模式下有参数 cin_used，缺省 "false" 时模型以 inverta 代替进位输入、无视已连接的 .cin 进位链。两网表中 cin_used/cin0_used/cin1_used defparam 均为 0 条；变体 6,699 个 arithmetic 单元中 6,194 个接有 .cin（全量 7,407 / 6,834），其进位链全部失效，**一切多位计数器卡死**。最小对照实验（取网表原样端口与掩码，Icarus 只编原语模块）：cin_used 缺省时第二位输出恒 0、置 "true" 后恢复正确。传播链：ram_init 计数器 cnt[1] 不翻转 → 计数卡住 → 状态机停在 S_TBL → init_done 永不置位；且 ri_we 恒 1、ri_addr 恒 0，RAM 写口多选（we/waddr/wdata 均由 ri_* 优先）把主机的全部配置写吞成写 0——§6.5 第一层适配重跑中里程碑齐全而仍零交付，正是此因。
- 适配方法（流程层，RTL 与综合网表逻辑零改动）：对网表副本做两层显式化（simfix v2，脚本 sim/psynth_bypass/vqm_simfix2.py）——端口层：缺 ena 补 .ena(vcc)、缺 inverta 补 .inverta(gnd)；参数层：对接有 .cin 的 arithmetic 单元补 defparam cin_used = "true"（变体 6,194 条 / 全量 6,834 条）。自检「LUT 依赖未接数据输入」为 0；v1 变体件与独立重生成 SHA256 逐字节一致（49550e36…）。原始 .vqm 不作任何修改。同类工具链的通行做法是由 EDA 网表写出器生成显式连接全部端口与参数的仿真网表（如 .vo）；本流程直用 .vqm，故需此适配。

### 6.5 第一层适配后重跑与微探针定位第二层（2026-11-04 上午）

### 6.7 全量网表：MAC 初始化阻塞与 simfix3（2026-11-04 下午）

- 核心侧先行确认（全量 simfix v2 网表 + 微探针）：P1–P4 全过——STATUS=0、init_done 于 144.992 µs 置位、配置回读三项正确、注入后 g_msgs=1，与 RTL 基准逐项一致；但 P5 六次轮询（396→1,646 µs，Elapsed 1:00:00）tx_frames/rx_frames/rx_msgs 恒为 0。即核心本体在全量网表上已被两层适配修复，剩余阻塞不在核心。
- 根因（IP 初始化在仿真时间尺度上不可达）：Tri_Mode_Ethernet_Mac_0 内部 mdio_top_mac 的 link 信号门控整条数据通路——发送/接收内部复位（tx/rx_mac_rst_n_d2）、发送就绪（tx_axis_mac_tready）与 GMII 发送使能（要求 speed=2'b10 千兆且全双工）均以 link 及 MDIO 配置结果为条件；而 link 须由 MDIO 读回 PHY 寄存器后才置位，MDIO 状态机的间隔计数器 rd_gap_time 经 LUT 掩码解码为 250,000,000 拍（clk25，10.000 秒）后发首次写、再 50,000,000 拍（2.000 秒）后发首次读——在毫秒级仿真窗口内 mdc 从未翻转、link 恒 0，帧在 MAC 入口被反压（组帧器停在第 16 字节、frame_done 不产生），与探针读数（tx_frames=0）吻合。RTL 级验证所用行为模型将 link/speed/双工直接置为常量（rtl/mac/mac_ip_behav.v 第 85–86 行），故 RTL 侧从未暴露此问题；该阻塞与官方规避方案中「跳过 MAC 初始化」的预设情形一致。
- 适配（simfix3，脚本 sim/psynth_bypass/vqm_simfix3.py）：以已验证的 simfix v2 全量件为输入仅作增量——(1) 两处 pause_tx_mac ROM 的 init_file_layout 由 "Port_A" 改为模型可识别的小写 "port_a"，并按 .mif 解码补入 mem_init0（地址 1–72 为 1）；(2) u_macA/u_macB 各 4 个 MDIO 状态寄存器单元（link、speed[1]、speed[0]、mac_duplex_mode）改 .ena(vcc) 并改绑 LUT 掩码，使复位释放后即取行为模型同值（link=1、speed=2'b10、mac_duplex_mode=1）。静态预检：8 个单元的现值掩码（AA00/F000/CC00/F000）与 .ena 连接逐一与预期相符后才动手；成品与 simfix v2 件相异仅 20 行、全部落在这 10 个实例内，自检 +mdio_fastlink=8、+rom_init=2。数据通路仍为 IP 门级网表本体，本适配只替代其初始化结果。
- 探针复跑（全量 simfix3 网表，13:51:57 起，Elapsed 0:15:54，Errors 0）：**DELIVERED**——P5 首轮轮询 tx_frames=1、rx_frames=1、rx_msgs=1（t=396.464 µs），mismatches=0，与 RTL 基准逐项逐纳秒一致。对照：同一网表未加本节适配时六次轮询全零（见本节第一条）。
- 短集（同库续跑 tb_delivery_short，14:09 起，Elapsed 0:46:33，Errors 0）：**PASS（delivered 3/3，payload byte-exact）**——#1 vlid=0xC len=1 t=803100000；#2 vlid=0xA len=100 t=807364000；#3 vlid=0xB len=2000（分片→重组）t=1889276000；PASS 行 t=1890276000。（交付时刻与变体略有差异，为真实 IP 数据通路时延，非异常。）
- 收口结论：综合后仿真在**正常版本（全量）网表**上取得主要业务通过证据（短集 3/3 + 分级取证逐项一致）；三层阻塞——网表端口默认值省略、参数 defparam 省略、MAC IP 初始化时间尺度——均定位到机制级并在网表副本上适配解决，RTL 与原始综合网表全程零改动。门级 e2e（6 封）未重跑，依官方口径以同版本完整综合网表的主要业务验证为准（doc/05 补遗）。

## 8. 未实现与边界说明

1. 接收端口 CAM（64 口 UDP 端口分发）：未实现，P1；`hrx_port`
   恒 0，评测以应用口 VLID 信封交付为准。
2. 管理平面 SNMP/ARINC 615A/RTC：未实现，交付主体为 AFDX 数据面（官方
   "615A/665 不做硬性要求"原话引证见 doc/05）。
3. IP rx_axis 方向：纯仿真无外接 PHY，rx_mac_aclk 域不可控——RX 链采用自研
   mac_rx（全量验收），IP 承担 TX 与 GMII 物理口（集成口径，非 IP 功能裁剪）。
4. `.vo` 门级网表路径不使用：后仿走 `.vqm + 三原语库`（工程 RUNBOOK）。
5. 门级仿真速率随网表适配状态差异显著：未适配网表因大面积冻结呈
   57.5~76.8µs/min 的 X 阻尼假象速率、仅端口层适配后实测 15.6µs/min、两层
   适配（simfix v2）后短集整跑 12 分钟内完成（§6.4–§6.6）；全量 e2e 后仿
   仍为长跑，以分离进程执行并按里程碑回收（§6.2）。
