# 官方答疑口径汇编（选题一 AFDX）

来源：中科亿海微官方 QQ 群答疑汇总（2026.09.04–2026.10.30）。与《选题指南》文本冲突或指南未写明之处，以本汇编为准。括号内为答疑日期段。

## 顶层接口

- AFDX_top 模板是整个 AFDX 端系统仿真模型对外的**应用数据接口**，所有功能模块封装在系统内部；内部各模块交互接口无统一要求，实现符合 AFDX 标准即可。（10.19-10.21）
- 评测期望：顶层激励文件中只需要注入 **VLID + 应用数据**，以便统一评测场景；赛题中的 TOP 指的就是这个可直接注入应用数据的封装文件。用于综合的 TOP 端口可自行设计，但须完成到最终应用数据的封装。（10.22-10.26）
- 推荐注入格式：连续的数据有效信号上升沿到下降沿为一条消息，其中**前两个字节为 VLID**；考虑各队实现差异，允许自定义并提供自定义规则（在文档中写明）。（10.27-10.30）
- tx_data 是 input 到 ES 系统发送端处理；rx_data 是 ES 系统接收端处理完毕后 output；数据流是**原始的有效载荷数据（包含 VLID）**。（10.22-10.26）
- ready 信号可以不用到：rx_ready 可以在设计中完全不使用；tx_ready 取值不做要求；官方自动测试不会检查 tx_ready/rx_ready；可理解为 valid=1 时数据有效，不要求 valid && ready 同周期才算传输。（2026.09.24-09.28 及 10.22-10.26 两次确认）
- 顶层时钟、位宽等信息应按作品方案要求实现；系统配置要在非顶层激励文件中完成，顶层激励只注入应用数据。（10.27-10.30）
- 可以在现有顶层接口基础上酌情增加新的接口（错误指示等信号可按系统实现细节添加）。（09.24-09.28 / 10.19-10.21）

## MAC 与 GMII

- 给 MAC 层的接口是 GMII；GMII 是 MAC 与 PHY 之间的接口。（09.04 / 09.30-10.08）
- 不需要自己实现以太网 MAC，可以调用 eLinx 工具里面的 IP；官方方案：eLinx 提供 MAC 控制器 IP 核 **Tri_Mode_Ethernet_Mac**，直接调用 IP 进行仿真，**对 MAC IP 进行两次例化**（A/B 两网）。MAC 是否用 IP 无强制要求，也可以自己写整个 MAC 链路。（09.24-09.28 / 10.11-10.16 / 10.19-10.21）
- MAC IP 是加密格式，但 IP 例化时会生成 `.vo` 文件，仿真时使用这个 vo 文件（ModelSim 可跑）。（09.30-10.08）

## 性能指标口径

- **100 Mbps 指有效载荷吞吐率**：在 tx_data 接口上，单位时间内（多 VL）注入的有效载荷字节数达到 100 Mbps 时，系统能稳定运行，不出现丢帧、队列溢出或阻塞。A/B 冗余副本在接收端只计一次有效数据。100 Mbps 以太网链路无法满足要求，需要配置成**千兆模式（GMII）**。（10.11-10.16 / 10.22-10.26）
- **时延**：任意 VL 的首个 tx_data 数据输入，到 rx_data 接收到该数据的总时长 < 1~2 ms（最坏情况）。该约束针对单帧处理/转发时延；一个跨多 BAG 的多帧分片消息的完成时间不受此约束。（10.11-10.16 / 10.22-10.26，两次"更改为"确认）
- **抖动**：同一 VL 多帧（帧长相同）端对端时延的最大值减最小值，包含 ARINC 664 协议中的 BAG 抖动，开发过程中直接测量 BAG 抖动亦可；参考：抖动 ≈ 最大时延 − 最小时延 − BAG 配置值；系统满负载下不出现三位数（µs）以上的抖动即可。（10.11-10.16 / 10.22-10.26 / 10.27-10.30）
- 吞吐测试的 VL 数量、BAG、帧长组合不统一指定，各队在系统正常规格配置下能完成即可；测试应至少覆盖变长帧场景，帧长集合需包含最小帧、最大帧和至少两种中间帧长；要求实现多 VL 并发能力。（10.11-10.16 / 10.27-10.30）
- 对 FPGA 工作时钟频率无单独规定，但**时钟频率要与接口速率匹配**。（09.30-10.08）

## 功能与评测

- **需要支持分片**（单条消息可超过单帧 1471 字节）。（10.27-10.30）
- "128 个发送 VL"指能配置 128 条 VL；VL 配置方式不限；应用数据在激励文件中注入。（10.22-10.26）
- 4096 接收 VL、完整性检查（SN/FCS 错误帧拒收）、A/B 双网冗余（单网故障）、SNMP、615A、RTC 等功能，由参赛者自建 Testbench 演示并在测试报告中给出结果，评测时根据代码、仿真、报告综合评估；不需要为评委额外引出 GMII 网络口、PPS 输入等端口。（10.27-10.30）
- SNMP、615A、RTC 分别按什么版本验收：不对协议版本做规定，也不提供参考激励，建议参考协议规范要求；**对 ARINC 615A 数据加载功能及 ARINC 665 文件格式解析不做硬性要求**，交付物为 AFDX 协议实现。（09.11 / 09.24-09.28 / 10.11-16）
- 仿真要求：需要参赛者自己编写仿真激励（文件）并验证内容；要求基于 FPGA 做仿真；最终评测会运行参赛者自己的 Testbench；评测通过 eLinx 调用 ModelSim，**需要综合后仿真**；128 路发送、4096 路接收和长时间性能测试若已在 RTL 充分覆盖，后仿可不全量重跑，用同版本完整综合网表验证主要业务即可。（09.04 / 09.11 / 10.11-10.16 / 10.27-10.30）
- 器件：不绑定 FPGA 器件型号，任意选择一款即可；官方答复推荐用 130-CSG484_H 部署单个 AFDX 端系统（资源应当足够）；**只需综合即可**（综合通过），不需要完成布局布线；资源占用不作为评分参考，能正常综合即可。（09.22 / 10.22-10.26 / 10.27-10.30）
- 提交：提交系统只有一个上传技术文档的地方时，把其他文档跟代码一起打包上传；测试报告中应包含完整的仿真测试记录；作品提交页面的开发板照片与演示视频，以仿真结果截图及仿真演示视频代替。（10.19-10.21 / 10.27-10.30）
- AI 工具使用是否需要声明：不关注相关信息。（10.27-10.30）
- eLinx 教育版不需要 license；本赛题全部通过 eLinx 编译及仿真，无需硬件平台。（09.20 / 指南）

## 补遗（2026-11-03 补登）：官方《最终问题汇总》（2026-10-31~11-02 批）

1. **后仿官方方法**：修改 post-implementation 仿真 .do 文件，将其中 .vo 路径替换为综合生成的 **.vqm** 文件，再用 ModelSim 仿真。本队 .vqm 路线与此一致。
2. **后仿规避方案（官方明文授权）**：MAC IP 网表存在加密、或初始化时间过长时，可在 RTL 充分验证的基础上，于后仿中使用简化 MAC+PHY 模型、初始化期间拉高 MDIO 时钟、乃至 RTL 旁路 MAC 通道；前提是不改变 AFDX 业务逻辑；**提交时恢复正常版本，并提供规避方案及涉及的代码文件**；可跳过 MAC 初始化；已完成材料不必重做、可复现即可。本队变体旁路实践见测试报告 §6.3 与 `sim/psynth_bypass/`。
3. 其余条目与本汇编既有口径一致，无第二处计划变更。选题二部分与本队无关。
