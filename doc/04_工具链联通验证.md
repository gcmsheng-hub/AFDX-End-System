## 三、K1 排雷：eLinx BRAM 推断检查（待用户 GUI 操作，10 分钟）

目的：确认 eLinx 综合器能把 `ram_init_test.v` 这种写法（4096×8、同步读、寄存输出、
$readmemh 初始化）推断成 Block RAM 而不是触发器阵列——这直接决定接收路径
LastSN 表 / VL 配置表的资源可行性。

步骤：
1. eLinx 打开（或新建）工程，`File → Add Sources` 添加 `sim/k1k2_bram/ram_init_test.v`，设为 top（工程目录需能访问到 `ram_init.hex`——若拷贝源文件进工程，把 hex 一起拷到工程源文件目录）。
2. `Flow → Run Synthesis`。
3. 判定（看 Design Runs 资源列 / Messages / 综合报告）：
   - **推断成功**：资源里出现 RAM/BRAM 原语类资源（1 块量级），FF 数很少（≤几十）；
   - **推断失败**：FF 数 ~4096、LUT 上千（地址译码/输出 mux），需改写 RAM 模板再试。
4. 把结果（资源截图或报告段落）记回本文件第五节。

## 四、ModelSim 手动安装指引（剩余唯一手动步骤）

> **2026 更新**：Intel 已停售独立的 ModelSim - Intel FPGA Edition，下载页现在只提供
> Quartus Prime Lite 25.1，其中附带 **Questa - Intel FPGA Starter Edition**——
> 它是 ModelSim 的直系继任者（同为 Siemens EDA 引擎，vlog/vsim/vlib 命令与 TCL 完全同族，
> 界面一致），**装 Questa 即等效装好 ModelSim**，eLinx 按下述方法对接。

eLinx 的行为仿真按官方手册调用 ModelSim（§3.1.3），装好后两处配置：
1. eLinx `Flow → Settings → Tool Settings → 3rd Party Simulators` 填仿真器路径；
   - Questa 安装目录通常为 `C:\intelFPGA_LITE\25.1\questa_fse_win\`（或自定义路径），
     可执行文件是 `vsim.exe`；
   - 若 eLinx 配置项硬性要求 `modelsim.exe`：先直接填 Questa 目录试一次；报找不到文件时，
     在 Questa 的 win64 目录内把 `vsim.exe` 复制一份改名 `modelsim.exe`（同目录 DLL 依赖自动满足，
     两者同引擎），再回填。
2. Simulation 库路径默认指向 `D:\elinx\eLinx3.0\Simulation\elinx_lib`（预编译库）。
   Questa 与 ModelSim 库格式同源，大概率直接可用；若报库版本不匹配，
   按手册 §11.4 重编（Questa 里命令一致：vlib + vlog 编译 `Simulation/verilog/*.v`）。

获取途径（按优先级）：
- **首选**：Intel 官网 → Quartus Prime Lite 25.1 下载页 → 文件列表/Additional Software 里找

  装完用 `vsim -version` 验证。与付费 Questa-Intel FPGA Edition 的差别（性能/容量/覆盖率等）
  对我们纯 RTL 行为仿真无影响——我们不用任何 Intel 加密 IP。
  与 QuartusLiteSetup*.qdz 放同一目录再运行安装器；若只装仿真器可跳过 Quartus 本体，
  器件库全部不勾（省几 GB 空间——我们只用它仿真 eLinx 的工程）。

### 排坑实录（Questa 接入 eLinx 的三个坑，后来者必读）

1. **免费 license**：25.1 起 Starter 版也需在 Intel Self-Service Licensing Center 领取（见上）。
   症状：GUI 双击"一闪而逝"。教训：**排查 Questa 启动问题一律先用 `vsim -c -do "quit -f"` 抓控制台输出**。
2. **vsim.exe 复制改名 modelsim.exe 行不通**：Questa 2025.2 有防篡改自检，
   报 `** Error: vsim.exe renamed to modelsim` 拒绝启动。
   **正确做法：复制同目录的官方 GUI 启动器 `questasim.exe` 为 `modelsim.exe`**（自检通过）。
3. **eLinx 生成的 do 脚本用 `-vlog01compat` 编译 Intel 器件库**，而
   `elinx_lib/altera_primitives.v` 里的 `` `begin_keywords `` 指令在该模式下报错
   → 整个 do 中断 → GUI 永不出现（表象就是"点按钮没反应"）。
   修复：给 `D:\elinx\eLinx3.0\Simulation\elinx_lib\altera_primitives.v` 打补丁
   （删除 `` `begin_keywords "1364-1995" `` 与 `` `end_keywords `` 两行，原件备份为 .orig）。
   纯 RTL 仿真用不到这些库，但 eLinx 每次都会强制编译。
4. 另：Settings→Simulation 的"仿真库路径"（elinx_lib 预编译库）会以 `-L` 进入 do 脚本，
   反斜杠路径被 Questa Tcl 转义损坏导致设计加载失败——**清空该设置即可**（纯 RTL 不需要）。
