# 第一篇 总体设计

## 1. 设计目标

按 ARINC 664 Part 7 在 eLinx（纯仿真、无硬件）实现 AFDX 端系统：应用数据接口收发、BAG 整形调度、SN/IC/RM 高完整性通信、IP 分片与重组、双网冗余（A/B）。交付主体为数据面；管理平面（SNMP/615A/RTC）未实现，如实口径见 §8 定案 12 与第二篇专题六。
评分：代码及仿真 40% / 设计文档 20% / 测试报告 20% / 技术指标 20%。

## 2. 系统架构（四层，按实现）

```
第1层 应用口      AFDX_top（竞赛模板端口外壳；应用数据注入/交付，见 §3）
第2层 协议核心    afdx_es_core
                  发送: host_arb→buf_mgr→tx_regulator→tx_scheduler→tx_frame_builder→mac_tx
                  接收: mac_rx→rx_parser→rx_vl_lookup→rx_integrity→rx_redundancy→rx_reassembly
                  公共: cfg_bus / timebase / stats
第3层 MAC         Tri_Mode_Ethernet_Mac IP ×2（A/B 两网各一，eLinx IP Catalog 生成）
第4层 线路        GMII ×2（125 MHz, 8bit, 千兆）
```

各模块的职责、接口与设计要点见 doc/10。存储以描述符队列 + 共享帧缓冲组织（buf_mgr 统一仲裁），接收 VL 表 4096 项、发送 VL 表 128 项，均为可配置上限。

## 3. 顶层接口语义（doc/05 官方口径）

- 端口名与选题指南模板逐字一致。**数据/valid 方向按官方答疑的应用口语义**：`tx_data[7:0]` 入、`rx_data[7:0]` 出、`tx_valid` 入、`rx_valid` 出；**ready 保留指南模板方向**：`tx_ready` 出（ES 恒 1，表示可接收应用数据）、`rx_ready` 入（应用侧就绪）。
- **注入格式**：`tx_valid` 上升沿→下降沿为一条消息；消息 = **VLID（前 2 字节，大端）+ 应用载荷**；允许超过 1471B（内部 IP 分片）。
- **交付格式（与输入信封对称）**：`rx_valid` 上升沿→下降沿为一条消息；`rx_data` 输出 = **VLID（前 2 字节，大端）+ 处理完毕的应用载荷**（IC/RM/重组后的净荷）。
- **ready 处理**（官方两次确认"可不用"，自动测试不查）：`rx_ready` 设计中不使用（应用侧可不连线）；`tx_ready` 恒 1；不做 valid&&ready 同拍握手状态机。方向保留模板原向，避免接线歧义。
- **系统配置不在顶层激励**：VL 配置（BAG/Smax/IC/RM 使能/net_mask/端口）经顶层 `cfg_*` 配置引脚完成（地址地图见 §4），顶层激励只注入应用数据。
- 仿真激励文件格式：hex 每行一字节；`msg_tx.hex`（VLID+载荷连续）+ `msg_lens.txt`（每行一条消息字节数）；期望金标准帧同格式（`golden_{A,B}.hex` + `frame_{A,B}.lens`）。

### 3.1 与选题指南顶层模板的对应关系

指南模板为 8 端口（clk / reset / tx_data / rx_data / tx_valid / rx_valid / tx_ready / rx_ready）。本设计顶层 `AFDX_top` 的对应情况：

| 模板端口 | 本设计 | 说明 |
|---|---|---|
| clk、reset | 同名同向 | 一致 |
| tx_data[7:0]、tx_valid | 名称、位宽一致；方向为入 | 模板按网络侧视角定义，本设计按官方答疑的应用口语义：应用侧向端系统注入数据，故为输入（依据见本节与文件头注释） |
| rx_data[7:0]、rx_valid | 名称、位宽一致；方向为出 | 同上：端系统向应用侧交付数据，故为输出 |
| tx_ready、rx_ready | 名称、方向与模板一致 | tx_ready 恒 1；rx_ready 不使用（官方：ready 可不用、评测不查） |
| cfg_addr/cfg_wdata/cfg_we/cfg_re、cfg_rdata/cfg_rvalid（增补 6 口） | 模板外增补 | 系统配置通道：官方口径"能配置、配置方式不限"；配置信号必须经顶层引脚进入综合网表，不可由内部悬空信号承担，故增补 |

即：模板 8 端口名称、顺序、位宽与本设计逐字一致；差异仅在数据/valid 四口的方向（有官方答疑依据）与配置口的增补（有综合可达性依据），均已成文说明。

## 4. 内部标准接口

握手规则（全局）：**valid/ready 同拍有效即传输；valid 拉高后不得因 ready=0 撤销，数据保持。**

**① 配置总线 cfg（1 拍读延迟）**
```
cfg_addr[19:0] cfg_wdata[31:0] cfg_we cfg_re -> cfg_rdata[31:0] cfg_rvalid
0x00000~0x00FFF 全局寄存器 | 0x01000~ 发送 VL 表(128×8字) | 0x10000~ 接收 VL 表(4096×2字)
0x18000~ 接收端口 CAM(64×4字，未实现) | 0x20000~ 统计 | 0x30000~ 管理平面(未实现)
```

**② 主机发送口 htx（流式，包级）**
```
htx_valid htx_ready htx_sop htx_eop htx_data[7:0] htx_vl[6:0]   // htx_vl 在 sop 时有效
htx_ts_ins htx_ts_off[10:0]                                     // 可选 one-step 时戳
```

**③ 主机接收口 hrx**
```
hrx_valid hrx_ready hrx_sop hrx_eop hrx_data[7:0] hrx_port[5:0]
hrx_meta: src_ip[31:0] src_udp[15:0] rx_ts_ns[63:0] vlid[15:0] net[1:0]  // sop 时有效
```

**④ 帧内部流（mac↔builder/parser）**
```
s_valid s_ready s_sop s_eop s_data[7:0]
```

## 5. 时钟方案与吞吐预算（定量）

- **时钟**：全设计单时钟域 **125 MHz**（GMII 位率 1 Gbps = 8 bit × 125 MHz）；MAC IP ×2 与核心同域。官方要求"时钟频率与接口速率匹配"，千兆 GMII → 125 MHz。
- **载荷吞吐口径**（官方口径）：多 VL 并发下，`tx_data` 注入的有效载荷字节速率达 **100 Mbps** 时系统稳定（不丢帧/不溢出/不阻塞）；A/B 副本接收端只计一次。
- **可达性计算**（限定表述）：
  - 线路能力：GMII 1000 Mbps/网。每字节载荷在线上开销 = (L_payload+47+20)/L_payload。
  - 最坏帧（1471B）：1471/(1471+47+20)=95.6%；最小帧（17B）：17/(17+47+20)=20.2%。小帧极值推导仅适用于载荷 ≥17B 的场景。
  - **100 Mbps 达标口径**：达标用例按帧长组合配置——最小帧/最大帧/两种中间帧长混合 + 多 VL 并发 + 相应 BAG 配置，以**平均载荷吞吐**衡量；不表述为任意 1B 小包流也能单独达标。
  - BAG 约束：带宽判据 **Σ_j (S_max,j + 67) × 8 / BAG_j ≤ R_line**（67 = 帧头尾 47B + 线上前导/IFG 20B；R_line=每网 1 Gbps；A/B 双网并行各承载一份）。
  - 双网各承载全部流量的 1 份：载荷 100 Mbps（混合帧长）→ 每网线速需求远低于 1 Gbps。
- **结论**：125 MHz 单域 + 双 MAC 双 GMII 满足 100 Mbps 载荷吞吐，无时钟瓶颈。实测结果见 doc/08 §7。

## 6. 指标定义与测量

| 指标 | 定义 | 测量点 |
|---|---|---|
| 端到端时延 | 任意 VL **首个 tx_data 输入 → rx_data 收到该数据**（单帧）< 1~2 ms；跨多 BAG 分片消息整体完成时间不受此约束（分片公式 p×BAG+jitter+tech） | timebase(ns) 打点：首字节入队时刻 → 交付时刻 |
| 抖动 | 同一 VL（帧长相同）端到端时延 max − min（含 BAG 抖动；开发中可直接测发送抖动） | stats 每 VL 记录 max/min |
| 吞吐 | 单位时间注入的有效载荷字节速率（A/B 计一次）达 100 Mbps 且不丢帧/溢出/阻塞 | stats 载荷字节计数 / 时间窗 |
| 满负载抖动 | 不出现三位数 µs 以上抖动 | 回归用例断言 |

## 7. 验证体系

- 方式：文件式协同仿真——Python 参考模型 `afdx_ref.py`（帧构造/IC/RM/重组金标准）生成激励与期望 → Verilog-2001 测试平台文件驱动 → 输出落文件 → `check_output.py` 全帧逐字节比对并独立核算 FCS、IP 校验和、SN 序列、分片几何与 BAG 间隔，判定 PASS/FAIL，不以看波形判对错。

## 8. 发送通路设计定案

以下为发送通路与相关机制的设计定案（冻结正文之外的增补定案，逐条注明内容性质；实现与验收情况见 doc/10 与 doc/08）。

1. **每 VL 发送队列深度 = 4**：BAG 整形下每 VL 每 BAG 至多发 1 帧，稳态积压 ≤ 1 条消息；深度 4 吸收 3 帧突发。**分片消息按"消息级描述符"只占 1 个队列项**，在出队侧逐 BAG 逐帧生成（p 片消息 ≤ p×BAG+jitter+tech），故大消息（如 8000B/6 片）不受队列深度限制。槽位核算：4 队列满载（各 1 条 8192B 消息 = 4 槽）+ 1 条接收中（≤4 槽）= 20 ≤ 32 槽。
2. **UDP 端口索引键 = 端口按 VLID 所在表项索引**：sport/dport 为发送 VL 表 W5/W6 字段，随 VLID（W2）一同经 cfg_bus 配置，无独立端口表；接收侧端口 CAM 原规划按 (VLID, UDP dport) 复合键命中，该 CAM 未实现（见 doc/08 §8）。
3. **max_len/Smax 计量层级 = 应用载荷**（每帧 UDP 载荷字节数 N）：入队检查单帧 N ≤ Smax、分片消息最大片 1464 ≤ Smax；与 §5 带宽判据 Σ(S_max,j + 67) 口径一致（67 = 帧头尾 47B + 线上前导/IFG 20B）。如需按完整帧长配置，换算 Smax_payload = Smax_frame − 47；doc/06 用例的 Smax 配置值在载荷层级下语义自洽。
4. **发送 VL 表项 8 字布局**（0x01000 + VL×8 + W；W7 保留）：
   W0 {en, bag_ms[7:0]}｜W1 Smax[15:0]｜W2 VLID[15:0]｜W3 net_mask[1:0]（bit0=A，bit1=B）｜W4 phase_us[15:0]｜W5 sport｜W6 dport。全局寄存器：0x00000 VERSION(ro)｜0x00001 UID｜0x00002 SRC_IP｜0x00003 CTRL(bit0=tx_en)｜0x00004 STATUS(bit0=init_done)｜0x00005 CFG_REJ_CNT(ro，VL 表非法写拒收累计)｜0x00006 CFG_REJ_FLAG(ro，拒收原因粘滞 bit0=BAG 非法 bit1=net_mask=00)。帧头 VLID 取表 W2（htx_vl[6:0]=信封 VLID 低 7 位作表索引，两者一致性由配置者保证）。
5. 预算注记：regulator 每 VL 计数+重装+en 约 4.5Kb 触发器；每 VL 发送统计 3×128×32b RAM 约 12Kb，均在存储预算红线内。
6. BAG 到期判定采用**严格大于**（cnt > reload，计数饱和于 reload+1）：µs tick 为自由跑相位，"重装后 1000 tick"实际历时可能少至 BAG−124 拍，用 ≥ 会使相邻帧 SFD 间隔最小到 BAG−1016 拍（端到端实测）；+1 tick 裕量后间隔恒 ≥ BAG（至多多 1µs，在抖动指标内）。
7. **cfg 写入门禁**：0x01000 区 W0 的 bag_ms 仅接受冻结集合 {1,2,4,8,16,32,64,128}（8 位非零 2 的幂即该集合），W3 的 net_mask=00（A/B 均不选）拒绝——非法写在 cfg_bus 截下，写使能不发出，表/regulator/buf_mgr 均不可见（读回保持旧值）；拒收累计记 0x00005 CFG_REJ_CNT（ro），原因粘滞位记 0x00006 CFG_REJ_FLAG（ro，复位清零）。
8. **phase_us 合法域 [0, BAG)**：W4 装载时封顶 cnt 初值 = min(phase_us, reload)——phase ≥ BAG 时至多延迟 1 tick 到期；W4 应在 W0 之后写（W0 装载"配置即到期"会改写 cnt）。
9. **RM SN=0 复位旁路增补：SkewMax 窗内副本去重**（设计定案）：RM 对 SN=0 保留复位重同步旁路，但按 VL 增加副本去重——RSN==0（上一接受帧即 SN=0）且距其交付时刻 elapsed ≤ SkewMax 时，再次收到 SN=0 判重复丢弃并计数；间隔 > SkewMax 的 SN=0 视为发送端再次复位，接受交付并更新 {rsn=0, t_last}。正常帧 SN 恒非 0，故 RSN==0 只可能来自 SN=0 旁路，RM 状态字无需扩展。验收用例见 doc/08 §3.2（rx5）。
10. **RM 距离公式定义域澄清：(sn,rsn)=(255,0) 记 old**（口径澄清，不改交付行为）：RSN=0 定为复位同步态、在模 255 距离公式 d=((sn−1)−(rsn−1)+255) mod 255 的定义域之外；该组合按 RTL 现行分支 d=255 记 old（丢弃，ev_rmold 计数），参考模型与 RTL、测试平台三方对齐（含 (255,0) 边界向量）。冻结公式在 sn,rsn∈[1,255] 域内与 RTL 式等价的结论不变。
11. **抖动口径并列：标准理论界（发送侧）与官方端到端实测口径**（增补）：标准理论界（ARINC 664 P7 §3.2.4，发送侧定义）：Max_jitter ≤ 40µs + Σ(20 + L_max)×8 / Nbw ≤ 500µs——40µs 为固定项，Σ 遍历各 VL（L_max 为该 VL 最大帧长），Nbw 为网络带宽，上限 500µs。官方端到端实测口径（doc/05，多次确认）："抖动：同一 VL 多帧（帧长相同）端对端时延的最大值减最小值，包含 BAG 抖动，开发过程中直接测量 BAG 抖动亦可；参考：抖动 ≈ 最大时延 − 最小时延 − BAG 配置值；系统满负载下不出现三位数（µs）以上的抖动即可。"两条口径并存不冲突：前者为设计期上界核算式（发送侧），后者为评测期端到端实测定义（接收侧、含 BAG 抖动）；测试报告按官方实测口径出具，设计文档引用理论界。注：理论式的标准精确出处页码为遗留核对项（见 doc/01），不影响实现与实测口径。
12. **管理平面如实口径：SNMP/615A/RTC 未实现，交付主体为数据面**（增补；§1 的实现状态以本条为准）：
    - 本作品交付与验证主体为 **AFDX 数据面**（BAG 整形调度、SN/IC/RM 高完整性、IP 分片、双网冗余、4096 接收 VL、分片/重组、错误管理、统计），SNMP/615A/RTC 管理平面子集**未实现**。
    - 官方原话引证（doc/05）："SNMP、615A、RTC 分别按什么版本验收：不对协议版本做规定，也不提供参考激励，建议参考协议规范要求"；"对 ARINC 615A 数据加载功能及 ARINC 665 文件格式解析不做硬性要求，交付物为 AFDX 协议实现"；"SNMP、615A、RTC 等功能，由参赛者自建 Testbench 演示并在测试报告中给出结果，评测时根据代码、仿真、报告综合评估。"
    - 测试报告同口径：管理平面按"未实现"如实记写，不列已测项。

## 专题一 虚拟链路与帧格式

### 规范依据

AFDX 以虚拟链路（Virtual Link，VL）为基本通信抽象：一条 VL 是单向逻辑通道，具有唯一的 16 位虚拟链路标识（VLID），发送端系统按 VL 组织发送调度，接收端系统按 VL 组织接收处理。本工程支持可配置 128 条发送 VL 与 4096 条接收 VL（按官方答疑口径，「128 个发送 VL」指系统能配置 128 条 VL，配置方式不限）。

AFDX 帧建立在 IEEE 802.3 以太网帧之上，帧结构（不计前导码、帧起始定界符与帧间间隔）为：目的 MAC（6 B）、源 MAC（6 B）、类型字段（2 B，0x0800 表示 IPv4）、IPv4 头（20 B）、UDP 头（8 B）、AFDX 载荷、填充（Padding）、序列号（1 B）与帧校验序列 FCS（4 B）。总帧长不超过 1518 B，单帧有效载荷不超过 1471 B；载荷小于 17 B 时以填充补足数据区最小长度，最小帧长 64 B。帧长算式为 L = N + Padding + 47，其中 N 为载荷字节数，Padding = max(0, 17 − N)；N = 1 时 L = 64，N = 1471 时 L = 1518。

地址映射规则如下：

- 目的 MAC：高 32 位为常量段，低 16 位为 VLID；首字节低两位为组播与本地管理标志。本工程常量段取 03:00:00:00（标准未规定该常量值，此为工业惯例取值，作为配置参数处理）。
- 源 MAC：常量段 02:00:00，其后为 16 位 User_Defined_ID 与接口标识字节；A 网接口标识字节为 0x20，B 网为 0x40。A、B 两网副本仅此字节不同，FCS 随之不同。
- 目的 IP：组播地址 224.224.VL[15:8].VL[7:0]，即由 VLID 直接映射生成；源 IP 为发送端系统的单播标识。
- UDP：源、目的端口按 VL 配置寻址；UDP 长度不含帧尾序列号；UDP 校验和默认取 0x0000（不启用），接收侧对校验和为 0 的帧不作校验、非 0 时可校验且失败丢弃并计数。

IPv4 头中标识字段按每 VL 计数，用于分片标识；分片时的标志与片偏移见专题五。

### 本工程实现

发送通路按 VL 配置表组织：每条发送 VL 配置 VLID、BAG（见专题四）、冗余使能、源/目的 UDP 端口、SkewMax（见专题三）等参数，配置在系统初始化阶段经配置接口写入，运行中按 VL 独立调度。帧组装由发送通路按上述字段顺序完成，FCS 采用 CRC32 覆盖自目的 MAC 至序列号的全部字节、低字节先发；接收通路先校验 FCS，再进入完整性检查与冗余管理（见专题二、专题三）。

应用数据接口按官方答疑口径设计：激励只注入 VLID（消息前两字节，大端）与应用数据，数据有效信号的上升沿至下降沿构成一条完整消息；系统配置在非顶层激励文件中完成。

### 验证方式

帧格式由参考模型逐字段生成期望帧，检查程序对每帧逐字节比对，并独立复算 FCS、IP 头校验和、帧长与分片几何；最小帧（1 B 载荷，64 B）与最大帧（1471 B 载荷，1518 B）均纳入定长与变长帧测试集合。

## 专题二 序列号与完整性检查

### 规范依据

序列号（SN）为帧尾一字节，范围 0~255，每条 VL 独立维护，规则如下：

- 发送端复位后，第一帧 SN = 0；
- 此后每发送一帧 SN 加 1，255 之后回绕到 1（0 仅在复位后出现一次）；
- 同一消息的 A、B 两网副本使用同一 SN，仅递增一次；两份副本应在 0.5 ms 内先后发出。

完整性检查（IC）在接收端按 VL、按网络分别执行，与冗余管理相互独立。记 PSN 为上一帧「收到」（不必然转发）的 SN，则当前帧 SN 的合法窗口为 [PSN+1, PSN+2]（加法按 255 回绕到 1 的规则理解，如 PSN = 254 时窗口为 {255, 1}）。无论当前帧被接受还是丢弃，PSN 一律更新为当前帧的 SN，即按「收到」而非「接受」更新，具备重新同步语义。两种特殊情形无条件接受：收到 SN = 0 的帧（表示发送端复位），以及接收端复位后收到的第一帧。窗口之外的帧丢弃并计数。IC 可按 VL 配置关闭，关闭时双网帧均予接收。

### 本工程实现

发送侧序列号发生器按 VL 独立计数，复位后首帧输出 0，此后按 1~255 循环；A/B 副本共享同一次递增。接收侧完整性检查的状态（PSN 及有效标志）按「VL × 网络」二维独立维护：两网各自判窗、各自计数，任一网的复位或故障只重置该网状态，不影响另一网连续运行。窗口判定采用无符号算术实现回绕语义，保证综合与仿真行为一致。

### 验证方式

完整性检查以穷举对拍验证：参考模型给出 SN 序列在窗口内、窗口外、回绕点（254/255/1）、复位帧（SN = 0）等情形下的期望接受/丢弃结果，与 RTL 逐项比对；双网独立性以单网复位、单网故障注入用例验证。

## 专题三 冗余管理

### 规范依据

冗余管理（RM）负责在 A、B 双网副本中交付一份有效数据。其基本语义为先到有效帧优先（First Valid）：两网中先到达并通过检查的副本被交付，后到的同一 SN 副本作为重复帧丢弃。RM 的接受/拒绝只以接收序列号（RSN）为判据（IC 为独立环节），且交付必须保持 RSN 递增序，不作重排序。

本工程采用环形距离窗判据（记为 MODE=1）：定义环形距离 d(sn, rsn) = ((sn − 1) − (rsn − 1) + 255) mod 255，其中 rsn 为上一交付帧的 SN。d = 0 为重复帧，丢弃；1 ≤ d ≤ 127 为新帧，接受；128 ≤ d ≤ 254 为旧帧，丢弃。每条 VL 配置 SkewMax（双网副本到达时间差上限，按拓扑配置）：若距上一交付帧的时间已超过 SkewMax，则下一帧无论 SN 为何均无条件接受，以保证单网长期故障或发送端重启后能重新同步。

旁路规则：接收端复位初态（尚无有效 rsn）或收到 SN = 0 的帧时，旁路距离窗直接接受，并同步 rsn 与时间戳，避免 SN = 0 在距离窗中落入旧帧区间被误杀。

RM 可按 VL 配置激活或关闭：激活时双网副本交付其一，关闭时双份均可交付。每条 VL 可配置为双网冗余发送或单网发送。

### 本工程实现

冗余管理状态按 VL 维护（上一交付 SN、有效标志、上一交付时刻），距离计算采用 9 位无符号减法加条件修正实现，禁止有符号取模，保证综合与仿真语义一致。SkewMax 以微秒级时间戳比较实现，按 VL 独立配置。需要指出单网丢帧的连带效应：若一帧仅在 A 网丢失，其 B 网副本可能因递增序约束被判为旧帧而丢弃，此为标准递增序语义的固有结果，本工程按标准语义实现，不作例外处理。

### 验证方式

冗余管理以穷举矩阵对拍验证：对 SN 与 RSN 的全部组合比对参考模型与 RTL 的接受/丢弃结果；另以双网时序用例验证先到优先、SkewMax 超窗接受、单网故障下另一网连续交付等场景。

## 专题四 BAG 与流量整形

### 规范依据

带宽分配间隙（BAG）是同一 VL 相邻帧起始时刻的最小间隔，取值限于 {1, 2, 4, 8, 16, 32, 64, 128} ms 八档，按 VL 配置。发送调度必须保证同 VL 帧起始间隔不小于该 VL 的 BAG；跨多 BAG 的分片消息，其各帧逐帧受 BAG 约束（见专题五）。

抖动的标准定义为同一 VL 帧实际发送时刻相对其理想 BAG 时刻的偏移；标准给出最大抖动的参考上界：不超过 40 µs 与各帧长相关项之和，且总上限为 500 µs。按官方答疑口径，本赛事抖动以同一 VL、相同帧长的端到端时延最大值减最小值度量（该度量已含 BAG 抖动成分，可直接测 BAG 抖动）；若时延本身已包含 BAG 成分，则不再重复扣除；系统满负载（队伍声明的最大规格）下不出现三位数微秒量级的抖动即可。

性能口径（按官方答疑口径）：100 Mbps 指有效载荷吞吐，即发送接口多 VL 注入的有效载荷速率，A/B 副本在接收端只计一次；为承载该速率，内部链路采用千兆 GMII。单帧端到端时延（任意 VL 首个数据输入至接收端输出）应小于 1~2 ms；跨多 BAG 的分片消息完成时间不受该单帧约束。

### 本工程实现

流量整形按每 VL 独立的发送许可机制实现，其口径与令牌桶/信用量模型等价：每条 VL 持有一份发送信用，信用以 BAG 为周期恢复，恢复后许可发送一帧（分片消息逐帧消耗许可），帧起始间隔因此不小于 BAG。调度器在多条 VL 同时具备发送许可时按轮询仲裁选择下一帧，保证单 VL 的 BAG 约束与多 VL 并发互不破坏。各 VL 另设相位偏移配置，使多 VL 的首发时刻在时间轴上错开，降低同刻竞争。系统内部为单时钟域千兆 GMII 链路，发送、接收处理能力按 100 Mbps 有效载荷目标设计。

### 验证方式

BAG 约束以逐帧时间戳验证：记录每条 VL 相邻帧的起始间隔并与配置 BAG 比对；抖动按官方口径以同 VL、同帧长的时延极差度量，覆盖最小帧、最大帧与至少两种中间帧长的变长帧组合与多 VL 并发场景，连续运行时间不少于 100 ms 量级。

## 专题五 分片与重组

### 规范依据

单条应用消息可超过单帧最大载荷 1471 B，此时必须分片（按官方答疑口径，分片为必备功能）：发送端在内部将消息按 IPv4 分片机制切分为多帧，接收端重组后交付，分片与重组对应用层不感知，外部只看到完整消息。分片几何遵循 IPv4 规则：除最后一片外，每片载荷长度为 8 字节的整数倍；各片共享同一 IP 标识（按 VL 计数），以 MF 标志与 13 位片偏移标示片序，片偏移以 8 字节为单位。每片仍是完整的 AFDX 帧，独立携带序列号并逐帧受 BAG 约束；分片消息的完成时间为多帧时间之和，不受单帧时延约束（见专题四）。

### 本工程实现

发送端分片由组帧通路按消息长度与单帧载荷上限自动切分，外部不需给出分片参数。接收端设置 2 个重组上下文并行跟踪多条分片消息的重组进度：上下文按（VL、IP 标识）建立，逐片校验偏移与长度的合法性（非 8 字节对齐的非末片、越界偏移等异常片丢弃并使该消息重组失败），全部分片到齐后按序拼接交付；上下文在消息交付或重组失败后释放。重组在冗余管理之后执行，即先完成双网去重、再对交付帧序列重组，避免重复片干扰。

### 验证方式

分片几何由检查程序独立核算：对分片消息逐片比对 MF 标志、片偏移与长度的 8 字节对齐关系；重组以变长消息（含恰好整除、带余数、单片即最大帧等边界）验证交付内容的逐字节一致性，异常片注入用例验证重组失败路径与上下文释放。

## 专题六 管理平面说明

### 规范依据

AFDX 标准体系另定义了管理与维护相关功能，包括简单网络管理协议（SNMP）、ARINC 615A 数据加载与 ARINC 665 文件格式等。按官方答疑口径：SNMP、615A、RTC 的验收不规定具体协议版本；对 ARINC 615A 数据加载功能及 ARINC 665 文件格式解析不做硬性要求，交付物为 AFDX 协议实现本身。

### 本工程实现

本工程实现范围为 AFDX 数据平面端系统：虚拟链路发送/接收、流量整形、完整性检查、冗余管理、分片重组与配置接口。**管理平面（SNMP、ARINC 615A 数据加载、RTC）未实现**，在此如实声明。未实现部分不影响数据平面功能的完整性与可验证性；系统配置通过配置接口在初始化阶段完成（见专题一）。

### 验证方式

本专题为范围声明，无对应测试项；数据平面各项功能的验证见专题一至专题五及测试报告。
