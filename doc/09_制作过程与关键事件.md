# 制作过程与关键事件

> 本文档记录本项目的制作历程：阶段划分、历次评审发现与整改、门禁设置、综合与后仿真攻坚、冻结交付。
> 记述口径：以职能与环节为纲——负责人负责需求裁决、方案定版、门禁验收与关键决策；实现、审查、测试环节借助 AI 工具按职能分工完成（模型一：主要实现；模型二：独立审查；模型三：方案与专项分析）。

## 2. 评审与整改事件线

本项目实行「实现与审查分离」：每批实现完成后，由审查环节独立走查（对照冻结规格与标准原文，而非对照实现自带的测试），问题经负责人裁决后整改、回归复验。关键事件如下。

**E1 分片边界缺陷（冻结终审发现）**：审查环节在接收重组路径发现分片偏移量位宽不足、大帧分片时偏移回绕。裁决整改：偏移计算改全宽比较。复验：全量回归全绿，缺陷销账。

**E2 假测试纠正**：审查环节枚举测试向量后发现，某网络层用例的激励并未真正覆盖其声称的场景（通过是假象）。裁决：该用例按真实场景重写激励。复验：78/78 向量真实通过。

**E3 回归门禁缺陷**：审查环节发现回归脚本某段缺少编译/生成门禁，失败可能被掩盖。先在故障注入沙盘中差分证伪、确认机理，再修复脚本。复验：回归判读恢复可信。

**E4 完整性/冗余算法穷举对拍**：IC/RM 两算法以独立金标准模型做全矩阵穷举对拍（327,936 向量），含乱序、越界尾片、非对齐拒绝等负向场景；审查环节提供的原始反例被固化为回归用例。

**E5 性能未达定性（PERF-05）**：128 条 VL 满载实测交付 4730/6400（74%），溢出计数 2429。定位结论：串行接收处理引擎在该规格点负载达 222%，属设计容量边界。负责人裁决：不返工、不掩盖，按未达如实入档（见测试报告 §7）。

**E6 冻结前文案复核**：提交文档冻结前经独立复核，指出三处文案级问题：回归 tally 的构成口径未写清、演示录像参数与实测不符、工程文件差异清单漏登两项。全部按实测修正后采用。

## 3. 综合攻坚两案

**综合挂死案**：早期综合在接收重组模块耗尽不收敛。定位为一处超宽位与加全宽归约的组合逻辑被综合器展开。整改：将归约拆为 16 片分段实现。复验：综合恢复正常耗时。

**网表空心案**：综合网表一度丢失整条配置链——追查为配置信号在核心内无驱动源、被优化删除。整改：配置通道改经顶层引脚引入（与官方「能配置、配置方式不限」口径一致），测试平台的层级后门赋值全部清除；仿真侧另设行为模型替身供 RTL 验证（不进入综合工程）。复验：五大功能模块在网表中完整在位，第 11 轮综合 0 错误，逻辑单元 51,444。

## 4. 综合后仿真攻坚

- **长跑终局**：第 11 轮网表 + 交付级测试平台，ModelSim 连续运行 13 小时 49 分，终局看门狗超时、交付 0/6（详见测试报告 §6.2）。静态核查确认回环连线在网表中完整，失败形态为动态卡点、帧被静默吞没。
- **短集诊断**：改用三封短集复跑定位，注入完成而零交付，与长跑同形态（同墙）。
- **官方旁路尝试**：按官方答疑授权的规避方案，制作简化 MAC 变体（与原模块同名同端口、内联简化 MAC、去除厂商 IP 与初始化依赖）：变体综合通过（逻辑单元较原设计下降 3,178、网表特征验网通过），RTL 级交付 6/6 且时序与正常版本逐拍一致；但门级短集仍为零交付（同墙）。由此排除 MAC IP 为卡点，根因未定，疑在门级网表与交付测试平台的交互层面。
- **止损裁决**：负责人在两条官方路线均有据可查地走完后裁决收官：后仿真未取得通过证据、如实入档；提交恢复正常版本，变体及说明按官方要求随包附上（sim/psynth_bypass/）。完整数据见测试报告 §6.3。

- **根因定位与闭合（2026-11-04，提交日续查）**：提交包锁定后，负责人授权在截止前续查后仿根因。先行自审发现交付测试平台从不回读任何寄存器——既往「配置完成/注入完成」里程碑仅为测试平台自报、并不证明配置落表，故障段实际未定，收官结论中「网表与测试平台交互层」的定性就此打开重查。方案复核据浓缩证据定案第一层：综合网表按惯例省略取默认值的端口（寄存器使能应为 VCC），而仿真原语模型未给该端口默认驱动，未显式连接的寄存器（变体 1,145 个 / 全量 2,245 个）自上电冻结——经日志告警条数（30,284 条）与适配脚本统计逐条互证、网表副本哈希逐字节互证而坐实。第一层适配（端口显式化）后重跑仍零交付，一度误判为仿真速率问题；负责人坚持以读数判案，新设微探针测试平台经配置总线回读状态与计数器分级取证，一跑定位第二层：网表同样省略参数 defparam，进位链使能参数缺省令模型无视已连接的进位链（变体 6,194 条 / 全量 6,834 条），全部计数器卡死、初始化序列停滞且配置写入被占位写口吞没——并以单原语对照实验坐实。两层适配（simfix v2，网表副本适配、原始网表与 RTL 零改动）后：微探针门级读数与 RTL 基准逐项逐纳秒一致，短集三类（最小帧/单帧/分片重组）在变体网表上 3/3 交付通过；其后全量网表再定位第三层阻塞——以太网 IP 核的 MDIO 初始化含以秒计的硬编码等待、其链路状态门控整条数据通路，在毫秒级仿真窗口内永不就绪——按官方「跳过 MAC 初始化」口径在网表副本上绑定初始化结果（数据通路仍为 IP 门级本体），全量网表探针与 RTL 基准逐项逐纳秒一致、短集同为 3/3 通过，正常版本口径闭合。完整机制、数据与更正记录见测试报告 §6.4–§6.7；中途误判在报告中如实更正，未以后来的结论覆盖先前的记录。

## 5. 门禁与纪律

- **基线冻结**：方案与接口在阶段 0 定版冻结，后续变更一律走评审—裁决—整改—复验闭环；
- **门禁判卷**：阶段门禁核对的是「代码是否符合冻结规格」，判据为全帧逐字节比对与独立核算（帧校验、校验和、序列号、分片几何、调度间隔由检查器独立复算），而非实现自带测试的通过率；
- **数字诚信**：文档中的全部数字只允许填真实运行输出，估计值必须标注口径；
- **未达如实**：性能未达、未测条目、后仿真失败均按原样入档，不以文案修饰。
