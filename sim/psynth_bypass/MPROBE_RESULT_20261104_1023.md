## 根因：simfix 缺 `cin_used`（arithmetic 进位链未生效）
- 网表 arithmetic 单元：变体 6,699（其中 6,194 有 `.cin`）、全量 7,407（6,834 有 `.cin`）；
  **`cin_used`/`cin0_used`/`cin1_used` defparam 在两网表中均为 0 条**。
- 模型 `stratix_asynch_lcell` 缺省 `cin_used="false"`：arithmetic 模式下
  `data = lut4(mask, a, b, iinverta, 1)` ——**用 inverta 当进位，忽略 .cin 链**。
- 最小实验（网表原样端口+掩码，Icarus）：
  `cin_used=DEFAULT: s0=0 co0=1 s1=0 co1=1 (s1 期望 1)` / `cin_used=true: s1=1`。
- 传播链：ram_init 的 `cnt[1]` 因进位被丢掉而不翻转 → cnt 卡住 → 状态机停在 S_TBL
  → `init_done` 永不为 1；且 `ri_we` 恒 1、`ri_addr` 恒 0，RAM 写口多选
  （`we=cw_we||ri_we; waddr=ri_we?ri_addr:...; wdata=ri_we?0:...`）**吞掉全部 cfg 写**
  → VL 表始终为 0 → E1′ 零交付。
- 修法（simfix v2）：对 6,194（全量 6,834）个有 `.cin` 的 arithmetic 单元补
  `defparam <inst>.cin_used = "true";`，其余（ena/inverta）保持不变。
